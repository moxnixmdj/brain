# Repair candidate broker — unadmitted draft

This is a bounded first step toward the repair execution broker, not an execution carrier or a publication authority. The existing fabric repair gate and unconfined-execution refusal remain in place. No registry, verifier evidence, or capability credit is changed.

## What exists

`canonical/runtime/repair_candidate_broker_v1.py` reads a selected, quiescent project into an immutable in-memory snapshot. It bounds file count, directory count, depth and bytes; refuses symlinks, hard links, special files and `.git`; uses no-follow file descriptors and checks file identities around reads. The caller is responsible for choosing a complete project tree and removing secrets before staging. The module can create a fresh copy under a trusted staging parent outside the selected source tree. It does not preserve file permissions or executability. It does not start a worker.

After a worker has stopped, the parent can snapshot the staging tree, compare it with the original, require exactly one declared Python target to change, and require the path layout and all other file bytes (including declared tests) to remain identical. It does not compare modes, ownership, timestamps or other metadata. The resulting assessment explicitly denies execution and publication authority and does not claim semantic acceptance. Wrong code that changes only the allowed target is deliberately still just an unverified candidate. The module does not import, parse, or execute candidate code.

The proposal can be converted into an **unsigned request** using `effect_broker_contract_v1.make_request`, binding the candidate, original and post-state digests and target to an effect request. The optional acceptance-subject constructor additionally binds the exact requested goal, task ID, requested learning mode, and the hashes of declared test bytes; its hash changes when those inputs or the candidate change. These fields are caller claims, not evidence that the tests are trustworthy or the learning policy was enforced. The original narrower request is not a substitute for this subject. This is not a grant. The existing `effect_broker_final_authorizer_v1` and `effect_carrier_guard_v2` require separate receipt resolution, semantic authorization, carrier enforcement and postconditions; no accepted repair grant or carrier is created by this draft. The candidate's snapshot and origin are caller-visible data, not authenticated evidence.

## Controlled integration

`canonical/tests/test_repair_candidate_broker_trusted_fixture_v1.py` uses a repository-authored seeded repair fixture: the existing adapter runs on the staged copy, the original source and external authored audit remain unchanged, and the staged result is scope-checked but remains unauthorized. A second four-fresh-process controlled run teaches, attempts a related held-out literal with learning disabled, tries it with an empty store, and then tries it with the taught store. All four pass the authored post-repair audit; the warm run reports a retained hit and zero search invocations, while the empty-store and disabled runs search. The disabled run makes no observed `sqlite3.connect` call after the worker's audit hook is installed and leaves the taught database bytes unchanged; this is not a proof that every possible memory channel is off. All results remain unapproved candidates. The audit is a second authored test, not independent-personnel verification. This test invokes the adapter directly and runs trusted fixture tests in host subprocesses; it is not a fabric test. It must only run in a disposable checkout with trusted code. Network isolation and disposable copying are not hostile-code isolation.

`canonical/tests/test_repair_candidate_broker_v1.py` exercises the staged copy, unapproved wrong-code candidate, unsigned request, scope changes, additions and deletions, symlinks, hard links, FIFOs, invalid paths, bounds and a simulated concurrent read change. A network-isolated disposable-copy focused run covering these tests, the trusted fixture, existing effect-broker checks, repair boundaries and related controls passed 220 tests. The static integrity guard reported 11 rules and no violations. These producer-run tests do not qualify a carrier or independently verify the work.

## Remaining security and integration work

- The source tree and staging parent are trusted and must be quiescent; path checks and before/after stats are not an atomic snapshot or protection against concurrent malicious rename, privileged attackers, network filesystems, or a worker with host filesystem authority. The caller must stop and isolate a worker before reading its staging tree. No caller-supplied boolean proves this.
- The staging copy and captured bytes may contain confidential material. There is no secret redaction, worker output quota, aggregate resource enforcement, syscall filter, reviewed carrier, descendant cleanup, or safe network capability. Do not use the candidate with untrusted code.
- Scope validation is not correctness, test authenticity, a security review, or learning validation. A worker success flag, hashes, and a test it controls do not prove the task. Separate acceptance in a qualified carrier must bind the exact original, patch, tests, scope and policy; retained records require their own validation and provenance.
- No code here publishes the patch or retained SQLite state. A future parent-side publication carrier must bind the accepted bytes and exact prestate, exclude symlink/hard-link and path races, address concurrent editors and crash/recovery, validate effects after commit, and honestly report uncertain partial effects. A pre-check followed by `os.replace` is not an atomic compare-and-swap. Do not add a permissive mock grant or self-authored verifier to bypass this problem.
- The RAW_GOAL policy is still disconnected from retained repair; the actual capability's independent-verification gate and frozen-template blocker remain. No matched enabled/disabled fabric loop or restart/reuse result exists yet.

The next useful work is a reviewed carrier design on a suitable host, a separately verified patch-acceptance and publication protocol, and honest action-contract admission. Retain the current refusal until those prerequisites are actually satisfied.
