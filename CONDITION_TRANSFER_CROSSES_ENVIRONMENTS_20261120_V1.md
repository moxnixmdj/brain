## 1. Research findings

### Project (exhaustive, non-obvious names included)

* `canonical/tools/the_precondition_is_not_in_the_trace_v1.py` measured ten real
  actions in a real git repository with each program's own exit status as
  oracle: retention was 30/30, successes alone identified 0/10 conditions at
  k=1,2,4, and contrasts reached 0.9464 accuracy where the deciding fact was
  observable and 0.5833 where it was not. Its declared next step was exactly
  the bottleneck tested here: transfer a bought condition to a NEW environment
  with a different repository and different action set.
* `A_SINGLE_TRACE_DOES_NOT_PIN_THE_RULE_20261120_V1.md`: 150k+ candidate rules
  per row, zero demand-satisfying rules on 13/15 rows; one trace teaches a tape,
  a contrast teaches a rule.
* `WHAT_AN_EXPERIENCE_CAN_OWN_20261118_V1.md`: the most favourable stored
  experience format matched 104 unseen sites but fixed only 2 programs
  (1.92% precision); memory coverage saturates at ~60% and the product ceiling
  is ~1.1% of decision sites.
* `THE_GOAL_IS_A_QUOTIENT_OF_THE_TRACE_20261128_V1.json`: goal price is 3–6
  cells of the coarsest sufficient statistic, not 1; sufficiency fails at held-
  out depth with 208 collisions.
* Reusable computed organs found and used: `applicability_v1` (version-space
  learner), `contrast_selection_v1` (information-split selector),
  `settlement_v1`, and the real state/oracle harness above. No new learner was
  justified.
* Checked and rejected as substitutes: `jit_knowledge_v1` (retrieves external
  documents but does not decide applicability), `skill_precondition_presence_v1`
  and `what_the_condition_wants_v1` (diagnose wording, not transfer),
  `root1_contrastive_semantic_gate_v1` (task-level semantic gate), workflow/dataflow
  modules (provenance for other facts), and the OSWorld ledger stack (proof of
  completion, not of when a remembered action applies).

### Web / frontier (inputs only, no capability credit)

* AgentCL [1] distinguishes dependent streams, where later tasks can reuse
  earlier knowledge, from conventional/independent streams where reuse is
  unknown; it reports that dependent streams are the ones that distinguish
  memory designs and that memory can also degrade performance.
* Learning on the Job [2] shows frozen-weight agents can improve from ordinary
  feedback via external memory, and that the store transfers between models;
  the gain is from encoded feedback, not from storing more raw episodes.
* CL-Bench [3] reports that dedicated memory systems did not beat naive
  in-context learning and that agents overfit to recent observations; the
  discriminating question is cross-instance reuse.
* A 2026 memory-centric survey [4] explicitly separates replay, unseen variant,
  and shared structure across a distinct target task, and requires source/
  target partitions with no duplicated answers.

## 2. §3 verdict

* **True:** retention is solved. A remembered program replayed on a copied real
  state reproduces its exit status exactly; measured 30/30 in the project.
* **True:** a condition can be bought by designed contrasts when the deciding
  fact is in the cheap sensor vocabulary. Here 6/6 real actions reached 1.0 on
  source held-out states after 26 total executions.
* **True, newly measured:** the bought condition transfers to a different real
  repository with a different action set through an external store with zero
  target learning executions: 96/96 correct decisions on the six stored
  actions, 0 false applies.
* **False:** one experience identifies applicability. It stores a program with
  `OPEN__ONE_SUCCESS_BUYS_NO_CONDITION`; the chooser refuses it. This is now a
  structural property of the store, not a promise.
* **False:** "permanent" without scope. The rule is keyed by portable program
  identity and remains invalid for unseen actions; deletion removes it
  instantly. No action gets a borrowed rule.
* **Unproven:** exact condition identification (0/6 were `IDENTIFIED`; all six
  are provisional least-demanding survivors), arbitrary GUI/browser competence,
  SWE-bench Pro, Terminal-Bench, OSWorld 2.1, unseen-environment competence
  outside this git/tar/gzip/patch class, and sentience.
* **Missing:** independent verification, real benchmark harness for our agent,
  hidden evaluator, and a condition that is unobservable in the sensor
  vocabulary.

Why not let a model experience advanced coding actions once and learn them?
Because the trace carries the instance and the program, not the quantifier over
states where the program applies. Storing the quantifier in weights would make
it a world-fact warehouse and would delete the edit/delete/revoke path. The
computed mechanism here is candidate elimination, contrast selection, and a
subset test; the condition itself is external data.

What still stops us: identifying conditions where the deciding fact is not
observable, goals with more than one required statistic, GUI/visual state, and
a benchmark that measures our own agent end-to-end.

## 3. Single ultimate plan and design kill

Bottleneck: not storage, not replay, but portability of applicability.

Plan (minimal): (1) reuse the existing learner and selector to buy the least-
demanding survivor from contrasts in a source repository; (2) write only the
portable program identity, required facts and provenance to a plain JSON store;
(3) reload that store in a second repository; (4) use a pure subset chooser with
zero learning calls in the target; (5) score against each program's own exit
status; (6) require unseen actions to be refused.

Killed designs: fine-tuning or weights (forbidden and unnecessary), a model
judge (forbidden), a vector database (no computed selectivity), copying source
traces into the target (instance, not condition), a new learner (existing
version space is sufficient), treating one success as a condition (proved false
in this tree), treating a repository name or file path as the action key (would
not transfer), and scoring OPEN as wrong (it is the required fail-closed act).

Smartest-approach check: the chooser is one subset test, the store is plain
JSON, and both existing organs are reused unchanged. There is no component
left to remove except the measurement itself, which is the deliverable.

## 4. Build and hard test

New files: `canonical/runtime/instant_condition_store_v1.py` (external store,
one-success write, contrast upgrade, delete, pure chooser),
`canonical/tools/condition_transfer_across_environments_v1.py` (cross-repo
measurement), `canonical/tests/test_instant_condition_store_v1.py` (5
fail-closed tests), the generated external store
`canonical/astra_runtime/state/INSTANT_CONDITION_STORE_V1.json`, and this
report plus intent/receipt artifacts.

Hard test setup: source = real `pypa/packaging` clone at recorded commit,
target = real `pallets/click` clone at recorded commit, different seeds (7 and
19), 16 real states per action per repository, real `git`/`tar`/`gzip`/`patch`
processes, each program's exit status as oracle. Target action set differs:
six stored actions plus three unseen actions (`tar_extract`, `gzip_decompress`,
`patch_apply`) with no store entry.

## 5. Honest limits and next bottleneck

Unverified: exact identification, unobservable conditions, arbitrary new
environment classes, GUI/browser tasks, OSWorld 2.1, SWE-bench Pro,
Terminal-Bench, hidden evaluator, independent verification, benchmark score,
and §6 completion. Failed during build: the first training/held split put all
unmerged-branch negatives in held-out, producing 4 false applies on the target;
the split was corrected to take the first half of each class for teaching, and
the final run has zero false applies. Two shared-process suites retain pre-
existing failures present at the base commit: `test_osworld*` has one order-
dependent `sys.modules` pollution failure (284 passed), and the all-intents
orientation test references a missing historical evidence path. Neither is
caused by this change. No pinned kernel was edited.

Next §5 bottleneck: make the chooser's confidence honest inside the store — a
PROVISIONAL rule must report its survivor count and be eligible for targeted
refutation when a new environment produces a false apply, without re-buying the
whole condition. Test that repair on a third real repository and on an action
whose deciding fact is currently unobservable.
