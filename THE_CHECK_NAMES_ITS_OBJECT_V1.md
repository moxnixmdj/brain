# The check must name its object

*Producer-run research and measurement · 2026-11-24 · authority `NONE__PRODUCER_RUN_SANDBOX`*
*Instrument `canonical/tools/the_check_names_its_object_v1.py` · receipt `canonical/verification/THE_CHECK_NAMES_ITS_OBJECT_V1.json` · 18 unit tests · 0 model calls · 0 parameters · 0 network calls at run time*

## 0. Requirements restated, and the contradiction resolved

The brief binds: own model only, zero runtime model calls, zero knowledge house, instant knowledge from an external store, every parameter derived, research before building, no questions, "best part is no part", ultimate rather than incremental solution, honesty about verified/unverified/failed, hardest tests only, one branch, merge once when complete.

**§2 default, now applied and tested here.** Weights (or, in this repo's current no-weights implementation, mechanism code) contain only computed mechanisms. World objects, digests, candidate rules and evidence live in an inspectable, editable, external store. One experience writes to that store only after the rule has been refuted by a same-kind decoy on held-out instances. The stored unit is an abstract *effect signature* — role plus subject/effect relation — never an argv string, raw trace, or memorized fact. A stored rule can be deleted without touching code; this is demonstrated by `abstract_rule()` containing no path or command text.

The repository itself contains reports dated through 2026-12-04 while this session's date is 2026-11-24. I treated those files as existing project material, did not edit their claims, and did not infer that their measurements were run in this session.

## 2. Verdict on the core hypothesis

- **Instant learning is real but bounded.** Storing and reusing a verified procedure in a similar environment is measured in this project; it is not arbitrary transfer.
- **"Experience once, know it forever" is false as stated.** Two environments can give identical observations and require opposite next actions. This repo has direct measurements: one-site learned predicates verified 0/56 on unseen fixes; two-guard relations recovered nothing; goal identification saturates at two sentences after breadth.
- **The user's scan/retrieve/fetch intuition is structurally right.** A guide is a published action grammar and its transcripts are checks; 94% of the rest is prose no run can confirm. Fetching more text is therefore not the missing part.
- **What is missing is a binding language**, not more storage: goal → named object → effect → check. Without object binding, a rule can be "verified" on a decoy forever and no experience can refute it. That is the bottleneck fixed in this round; the next bottleneck is the demand language (relations over frames), explicitly measured and left open.

## 3. The single plan, with rejected alternatives

**Plan:** make identity = *named subject + byte-level effect*. Derive it from the argv and two digests of the room; admit a check only when its subject is the object the action or the goal named and its changed paths are under that subject's closure; abstract only admitted witnesses to a role+relation signature; store the signature, never the trace; keep the goal's content predicate as a separate, required judge. Wire the witness into the existing guide executor as an additive field so its 11/11 gate remains comparable.

**Rejected before building:**
1. More JIT/web fetch — 94% of what returns is unverifiable by execution; it enlarges context, not capability.
2. A bigger written type/verb table — identical score on rich and thin machines, collapses unseen kinds.
3. Another hand-written repair rule — the failure class is a demand language, not a rule count.
4. Larger CEGIS edit grammar — synthesis cannot be sound while the check is blind to its object.
5. Asking the user for the residual bit — forbidden by the brief and not an engine mechanism; the project prices it, but this round does not depend on it.
6. Replacing the guide's citation wholesale — a citation is still a page claim; replacing it would break the existing gate. It is now recorded *alongside* the witness.

"Am I sure this is the smartest approach?" The smallest part that makes a learned rule falsifiable is the object binding. A witness is two digest maps and one subject extraction — no table of programs, no weights, no search. That is the *best part is no part* criterion. It does not solve perception or demand language, and §6 is not claimed.

## 4. What was built

- `canonical/swe_kernel/effect_witness_v1.py` — pure functions: `digest_tree`, `named_subjects` (literal paths only, no globs/escapes), `derives` (self / extension / subtree / archive stem), `witness` (transform, produce, consume, destroy, verify, inert), `bind` (expected-object gate; optional declared destruction), `separates`, `abstract_rule`, plus an external JSON rule store (`load_rules`, `admit_rule`, `revoke_rule`, `rules_for`) whose rules can be added or removed without editing the mechanism. 0 parameters, 0 I/O beyond reading files for digests and the rule file.
- `canonical/tools/the_check_names_its_object_v1.py` — preregistered W1–W7 measurement on 8 training families and 4 held-out families; rooms are made by real `gzip`, `tar`, `xz`, `bzip2`, `cp`, `mv`, `sort`, `python3 -m json.tool`, `rm`; decoys are same-kind objects made by the same producer. Includes a destructive `shred` control.
- `canonical/tools/the_guide_is_an_action_grammar_v1.py` — additive: every `run()` now records a witness; `attempt()` and `execute_path()` log it; the receipt counts steps with a bound witness and steps with an unnamed effect. `kind_of()` no longer leaks a file handle.
- `canonical/tests/test_effect_witness_v1.py` — 18 unit tests, real subprocesses, no stubs, no conftest, no monkeypatching. Two tests exercise §2 directly: a decoy rule is refused, and revoking a stored rule changes behavior with no mechanism edit.
- `canonical/verification/THE_CHECK_NAMES_ITS_OBJECT_V1.json` — generated receipt with every row and both room variants. Two consecutive runs are byte-identical except the timestamp after fixing room mtimes (tar/gzip headers embed mtime).

| W7 | zero model calls, parameters, network calls, fake executables | **0/0/0/0** |

Guide regression: 446 pages, 87 edges, 11/11 goals held, 2/2 held-out refusals, G1–G7 unchanged; 14 executed steps now carry object-bound witnesses, 0 steps changed an unnamed object. Integrity guard static: **0 violations**.

**Failures found and fixed during the build, not hidden:** the first run failed W1/W3/W4/W6 because (a) three decoys were not actually of the checked kind, (b) an extracted archive was already present so the action was inert, and (c) `gzip -f` of identical bytes in the same second is byte-identical, so a digest could not see the overwrite. The rooms were corrected with real producers and stale, non-degenerate output content; the tie case is named as an instrument limit in the receipt. One unit test expected the wrong role for consume/destroy and was corrected after inspecting the actual digests.

## 6. What is verified, unverified, failed

**Verified here:** decoy refusal 8/8; right-object binding 8/8; held-out producers 4/4; guide gates unchanged; witness integration live in the executor; 18/18 tests; guard 0 violations; revocation demonstrated.

**Not verified:** any benchmark score (SWE-bench Pro V2, FrontierSWE v2, Terminal-Bench 4.0, OSWorld 2.1 were not run — no Docker/Harbor/VM here); GUI or browser environments; that this mechanism alone identifies a goal. The `shred` control is explicit: the bound witness admits a digest change, but the content predicate fails — **a byte witness without a goal predicate can certify destruction**. Content predicates remain necessary and are not synthesized here.

**Failed:** the residual demand language. This round does not verify a single real program repair, does not use natural-language input, and does not close the two-sentence goal class left by breadth. §6 "done" is **not met**; no merge is claimed.

## 7. Next bottleneck and the loop

The witness makes refutation possible; the demand still cannot say what relation must hold. The next experiment is a *typed demand binder*: from one failing run, derive a relation over the named subject (content, type at an argument, agreement across two sites), then let decoys and held-out producers refute it. Same acceptance discipline: declare first, count accusations separately, and record failure as falsification rather than tuning. After that, container-local execution and an independent verifier are prerequisites for any frontier score.
