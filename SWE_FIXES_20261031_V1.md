# SWE fixes V1 — never certify a wrong answer

The first two fixes from `HARDCORE_SWE_PROBLEMS_20261031_V3.md` §10.1, landed and measured on
`main` `4b1baa2` (the tree V3's rows were re-read on). Both are predicates; neither adds a
capability, an adapter, a model call, or a dependency.

| # | defect (V3) | fix | mechanism reused |
|---|---|---|---|
| 1 | §2 — a request to extract is answered with a count, and certified (§1-A, 5 of 62) | `answer_shape_v1.deliver()` at the door's single exit; refusal is `ANSWER_SHAPE_UNSERVED` | the artifact the adapter already wrote, hashed and verified |
| 2 | §3 — a read is certified as a rewrite (`revert`→`log`, `reset`/`stash`→`status`, `push`→`branch`) | the sentence's own verb is bound as the operation; the row refuses by name | the row's `OPS` release and its `OP_NOT_DECLARED` refusal |

Cost of both gates, measured: `asked()` is **7–21 µs** per sentence; nothing else runs unless the
sentence asks for a collection. 13 new tests run in **0.084 s**.

## 1. The answer must be the answer

The adapter writes the requested bytes to its artifact, hashes them, verifies them, and the door
returns the summary. Five of V3's seven wrong PASSes are that one skeleton.

| sentence | before (V3 §1-A) | after (measured now) |
|---|---|---|
| `Find every caller of build_plan in …/swe_typed_plan_v1.py` | PASS `{caller_index_size: 8, call_edge_count: 236739, symbol_count: 92726}` | PASS, `answer = {"callers_of": …, "noun": "caller", "field": "callers_of"}`, narrowed to `{"build_plan": ["plan_report"]}` |
| `List the functions in …/swe_typed_plan_v1.py` | PASS `{function_count: 10}` | PASS, the 10 real names from `files[0].functions` |
| `Show the imports of …/swe_typed_plan_v1.py` | PASS `{distinct_imported_module_count: 5}` | PASS, `["__future__","canonical","pathlib","re","typing"]` |
| `Show the definition of _family_terms in …/swe_typed_plan_v1.py` | PASS `{answer: 10}` | **FAIL_CLOSED__ANSWER_SHAPE_UNSERVED**: `python.source.definition_count.v1:definition:NO_MATCHING_FIELD` |
| `Find duplicated code in canonical/runtime` | PASS after 94.6 s | **FAIL_CLOSED__ANSWER_SHAPE_UNSERVED**: `code.index.tree_sitter.incremental.v1:duplicate:ARTIFACT_TOO_LARGE:108260136` |

Two of the five are now answered from bytes that were already on disk. Three are refused instead
of lied about, and each refusal names the capability, the noun and the reason the projection
failed. Rows 4 and 5 are *not* fixed — they are now honest failures, and they stay on the list
below.

What the predicate reads, in order (all of it from the row's own output, nothing invented):

1. **the shape**: the sentence asks for members only if an enumerating verb is used (`list`,
   `enumerate`, `name`, `show`, `give me`, `print`, `dump`, `find every`, `find all`, `what are
   the`, `which`, `who`) or `find <a noun this table enumerates>`; the noun is the FIRST one the
   sentence names, not the first one the table lists — read in table order, *"Which commit broke
   the tests"* would have been answered about **tests**, and that sentence is one of the five
   answers that is already correct. `how many` is the one shape where a count **is** the answer,
   and the gate stays out of it.
2. **the field**: breadth-first over the result (`callers_of`, `functions`,
   `distinct_imported_modules`, `rows`, …), skipping count-suffixed names, envelopes
   (`output_path`, `schema`, `op`, `observed_effect`, …) and **anything under `totals`** —
   `totals.functions = 10` was outranking `files[0].functions`.
3. **the artifact**: only if the result holds no answering field, the artifact the row itself
   declared is read — never over 16 MB, never outside the repository, never parsed whole when a
   single field is asked for. The 108 MB `code.index` artifact costs 2 s and ~1.5 GB RSS to load;
   it is refused unread.
4. **the value**: copied verbatim, narrowed to the key the sentence names when it names one
   (42 callees in the file, one of them asked), bounded to 50 entries with `truncated: true`.

Where it runs: `_close_observations`, the one function every exit of the door passes through,
next to the identical `observed_effect_errors` rewrite that was already there. A pass carries
`runtime_status_before_answer_shape_check`, so the original status is never lost.

## 2. The verb is the operation

V3 §3 asked for *"an unmatched verb must derive no operation"*. Implemented as the stricter
option available at the same place: **the stated verb is bound**, and the row refuses the
operation it does not declare. Nothing is derived from the noun phrase beside the verb, and the
refusal is the row's own words rather than a second vocabulary written here.

```
before                                   after
Revert the last commit    PASS op=log     FAIL  GitOperateError:OP_NOT_DECLARED:revert:declared=log,status,diff,show,blame,branch,commit
Reset the working tree…   PASS op=status  FAIL  …OP_NOT_DECLARED:reset:declared=log,status,diff,show,blame,branch,commit
Stash the working tree…   PASS op=status  FAIL  …OP_NOT_DECLARED:stash:…
Push the current branch…  PASS op=branch  FAIL  …OP_NOT_DECLARED:push:…
```

Row 1 is the most damaging signature in V3 (§3): a caller who reads `pass: true` after a revert
does not look again. All four are now refusals that name the operation and the row's seven
declared operations.

**Measured again after merging `origin/main` (which landed its own stated-effect gate on this
same file — the two changes are complementary, not duplicates):**

```
Revert the last commit          FAIL_CLOSED__STATED_SWE_EFFECT_UNSERVED  (refused upstream, before the binder)
Reset the working tree to HEAD~1  FAIL_CLOSED__STATED_SWE_EFFECT_UNSERVED  (refused upstream)
Stash the working tree changes    FAIL_CLOSED__STATED_SWE_EFFECT_UNSERVED  (refused upstream)
Push the current branch to origin FAIL  GitOperateError:OP_NOT_DECLARED:push:declared=log,status,diff,show,blame,branch,commit
```

Main's gate refuses three of them a layer earlier; the verb binding is what still decides `push`,
and it is the only one of the two that keeps the *stated operation* faithful instead of refusing
the sentence wholesale. Both are kept, and the test pins the binding itself, so the refusal can
never silently revert to a read.

What did **not** move, by construction — an operation the grammar already reads keeps its reading
byte for byte, because only a *write* verb the row does **not** implement may override it:

```
Show the last three git commits    log      (verb "show", means log — unchanged)
List the branches                  branch   (unchanged)
Show the status of the working tree status  (unchanged)
What changed in the last 5 commits  log     (unchanged)
Commit the staged changes           commit  (unchanged)
Commit the transaction to the database  —   (no repository context: still no operation)
```

The vocabulary is git's own (`git help -a`, porcelain commands), never a list of words this file
invented; the leading word is read after a bounded set of openers (`please`, `could you`, `now`,
…), so a question or a lookup states nothing: *"Which commit broke the tests"*, *"Find every
caller …"*, *"Explain why the push failed"* bind no operation at all.

**Correction to V3's plan, stated openly:** §10.1 said the rewrite verbs should "derive no
operation and refuse". They now derive the operation and are refused by the row. Same verdict,
better reason: the refusal names the operation and the declared set, and it is produced by the
component that will have to implement the operation if it is ever added, so it cannot drift from
the row's real release.

## 3. What this does not fix, measured

**3a. Retracted: the two sentences I measured as refused now pass.** On `4b1baa2` I measured
`Show the status of the working tree` and `What changed in the last 5 commits` refused with
`NO_COMMAND_SLOT_FOR_THE_STATED_COMMAND` after retrieval selected a code indexer. That was true
of that tree; `origin/main` has since fixed it. On the merged tree both PASS with the right
operation (`op=status`, `op=log` respectively). The composer's own argv for them is still wrong
(`git status --porcelain` for *"the last 5 commits"*, `git log -n 20` for *"the last commit"*), so
the composer route is still not the answer for those sentences — but the refusal I reported is
gone and this document must not keep claiming it.

**3a-bis. A pass over a non-collection read carries no `answer`.** `Show the status of the working
tree` and `What changed in the last 5 commits` now PASS with the correct `op`, and the rows are in
`execution[0].result.rows`, but the top-level `answer` is `null`: the projection only lifts the
collections a sentence *names*, and neither sentence names one from the table. That is deliberate
scope, not a defect in the gate — the next two-line extension is a `status`/`change` noun whose
alias is `rows`.

**3b. The two honest refusals in §1 are still capability gaps.** `python.source.definition_count.v1`
declares `answer` and `definition_count` and no list; `python.source.symbols.index.ast` is the row
that *does* hold `definitions`. The projection gate is the wrong place to fix either.
