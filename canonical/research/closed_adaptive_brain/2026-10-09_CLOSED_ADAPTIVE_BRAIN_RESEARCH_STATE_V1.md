## Research synthesis: Closed Verified Cognitive Fabric

### M1. Universal Cognitive Fabric
Use one typed capability/state/effect protocol over native verified engines. Do not rebuild each subsystem.

A capability is modeled as:

```
(preconditions, inputs, effects, outputs, verifier, scope, cost, failure_conditions)
```

### M2. Lossless Intent + Belief Refinement
Do not require one magically perfect interpretation of arbitrary language.

Maintain admissible interpretations/worlds/constraints/acceptance laws. If every admissible interpretation yields the same adequate policy, execute the common policy. If policies differ, acquire the cheapest truthful discriminator that can change the policy, then refine.

This generalizes the Brain's CEGAR/minimum-information work and avoids wasting effort resolving irrelevant ambiguity.

### M3. Universal Acceptance Kernel
Correct tool execution is not the same as satisfying the user's real goal.

Compile the goal into obligations and give each obligation an independently checkable verification route: formal check, exact comparison, numeric proof, grounded evidence, metamorphic test, execution test, adversarial test, constraint solver, robust common-policy certificate, or bounded qualitative relation.

The reusable abstraction is **proof-carrying actions**: result + effect certificate + provenance + resource receipt + acceptance evidence.

### M4. Counterexample-Guided Self-Improvement Ratchet
Use real counterexamples to repair failure classes, not individual task instances:

```
outcome → verify → counterexample → causal diagnosis
→ minimum repair effect → existing architecture search
→ new primitive only if required
→ independent verification → regression/generalization
→ promotion → rerun
```

### M5. Option-Preserving Pareto Superoptimization
Keep multiple equivalent verified routes and select the best route under the current resource model. Retire dominated routes from the active frontier, but do not physically delete future option value without separate proof.

Optimize capability/generalization/reliability against latency/compute/memory/verification cost/spend.

The deepest reusable pattern is:

```
EXPAND → DISCRIMINATE → COMPRESS
```

over candidate world / intent / policy / program hypotheses.
