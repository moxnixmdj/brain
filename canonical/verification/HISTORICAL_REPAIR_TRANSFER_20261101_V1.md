learning results. It did **not** establish arbitrary historical learning, an all-in
optimality result, or full completion of the harder cross-file roadmap.

## Causal diagnosis and bounded implementation

The original byte-unit failure was **not absent localization**: actual execution
ranked `bytes2human` first. Its repair is the existing `<=` to `<` mutation.
Nevertheless, `_pool` contained no comparison at legacy caps 8 **or the actual
default 24**. The correct mutation appeared at legacy index 25 when inspecting
cap 128. Earlier literal/docstring candidates exhausted the available slots.

A separate pre-edit probe using the default 24 failed with **62 subprocesses /
15.889s**. The repaired solver succeeds at that same bound; the final paired cold
runs used **63 subprocesses** each. This is not credit for merely enlarging the
initial eight-slot diagnostic budget. Initial eight-slot results remain in the
JSON and must not be used as a cost-matched comparison against final 24-slot runs.

Changes:

1. `_pool` optionally appends at most four comparison edits per guided file,
   excluding edits already present. Its default caller behavior is unchanged.
2. Provenance-guided repair executes that reserve only as additional singles,
   after existing singles. Original edit slots/order and pair-product membership
   remain unchanged; no new operator or model is introduced.
3. Diagnostics distinguish base inventory from total single inventory and count
   reserve singles in reported candidate-count reduction.

The additional singles can consume shared wall time before pairs. There is **no
universal speed or frontier-preservation guarantee**. Existing nonmonotonic
cross-file pair tests remain passing. Rename refusal, scoped applicability,
mutated-twin verification, actual-corpus gates and rollback are not weakened.

Both arms use the same maintained solver and live-trace fallback: 24 legacy
mutations/file, two guided files/symbols and 12 pairs. Only the explicit scoped
`retained_learning` option is disabled in the baseline; this is not removal of
every pre-existing default/learned mechanism in Brain.

That is **one of two distinct held-out issues solved per arm**, with two
repetitions, not four independent unseen issues. Teaching adds approximately
0.50s per boundary run and 0.47s per zero-consumption run. Enabled byte-unit runs
also spend two additional verification subprocesses automatically retaining the
successful search result. There is **no demonstrated distinct-issue success or
speed advantage from teaching**; the measured improvement belongs to the shared
solver.

The Bits lesson crystallizes. Insertion-only `ichunked` teaching is refused with
`FAILED_MUTATED_TWIN_VERIFICATION`. Direct diagnostics confirm whole-module token
patterns of roughly 28,000 tokens / 1,882 holes fail to reproduce their supplied
fix. A mixed docstring/code byte-unit rule also fails self-match; the single code
hunk found by ordinary search does crystallize. These are measured remaining
representation limits, not reasons to bypass verification. First-match-only is
inspected but has not been demonstrated as the dominant historical blocker.

## Negative controls and same-issue replay

- **Misleading similarity:** append an explicitly authored inclusive-threshold
  helper to the byte-unit project. The Bits pattern syntactically matches but
  would incorrectly reject equality. The actual project oracle rejects retained
  reuse; fallback repairs the real byte-unit bug and preserves the decoy and tests.
- **Changed source revision:** teach under the Bits snapshot revision, then supply
  the actual different pinned byte-unit revision as declared dependency context.
  Applicability is false, memory oracle calls are zero, and ordinary search still
  repairs/audits the target. Context is trusted caller input, **not automatic
  environment attestation** or an interpreter-upgrade test.
- **Same-issue replay:** ordinary search on a fresh byte-unit project takes
  **17.436s / 65 subprocesses**, automatically retains its verified code-hunk fix,
  and a new process repairs another fresh copy in **1.983s / 3 subprocesses** with
  a memory hit and zero search. Separate audit passes. No expert solution is
  supplied to either application. This is a useful replay result, not new-issue
  generalization or an all-in campaign speedup.

## Decision

Keep the small demonstrated solver repair and existing safety boundaries. Do not
promote historical learning on these results. The next justified learning work is
self-reproduction/twin-safe insertion and multi-hunk representation using existing
machinery, followed by distinct-issue and actual multi-source-file qualification.
Full discovery/recovery metering and broader concurrency/crash/version/inventory
stress remain open. This batch is not proof of permanence, universal computer
mastery, perfect engineering or sentience.
