# Scoped retained-skill verification and restart qualification

## Result and boundary

Implemented the approved next batch in the existing SQLite/pattern learner. This
is **self-run, bounded qualification**, not independent certification, universal
mastery, sentience evidence or completion of the six-phase curriculum. No
capability, ownership, benchmark or terminal promotion is claimed.

## Implementation

- Legacy booleans remain compatible but receive `CALLER_PREDICATE` assurance;
  truthy mappings and syntax-only callbacks cannot become `TEST_SUITE` evidence.
- Typed current results bind candidate SHA256, kind and declared scope. Actual
  project testing reuses the maintained copied-tree measurement and suite runner;
  passing requires nonempty tests, a zero exit code and measurement hashes.
- Versioned metadata lives in the existing `pattern_json`: scope, exact typed
  dependency constraints, declarative preconditions, parameter holes, proposed
  effects/invalidators, provenance, and distinct original/twin evidence. Contract
  identity prevents two scoped hypotheses colliding. Unknown constraints refuse.
- Counterexamples persist; duplicate teaching does not reactivate invalidation.
  SQLite generation triggers/file identity refresh the process cache after
  another writer's changes or deletion. Public lookups return detached copies.
  A final live-row check handles invalidation while a verifier was running.
- Existing compiler-oriented callers retain compatibility and their existing
  compiler gates; an untyped callback stays a caller predicate, even if its name
  suggests a compiler. No legacy record is automatically behavior-qualified.

The separate `executable_skill_verification_authenticator_v1` remains the existing
independent-receipt boundary. Local typed measurement records neither replace it
nor grant authenticated executable-skill authorization.

## Actual restart and causal controls

Two separately constructed Python package projects are used: a ledger package
with an accumulator and a held-out workshop package with invoice aggregation.
Only one subtraction-to-addition repair pattern is taught. Each stage below runs
in a fresh interpreter; source and tests in both original projects remain intact.

| Stage | Retained rows | Oracle calls | Result |
|---|---:|---:|---|
| Held-out original behavior | 0 | 1 | Three tests execute; suite fails |
| Cold recall | 0 | 0 | No repair |
| Teach on ledger project | 1 | 2 | Failing original / passing repaired suite |
| Recall on workshop after restart | 1 | 1 | Repaired copy passes three tests |
| Learning disabled | 1 | 0 | No repair |
| SQLite artifact removed | 0 | 0 | No repair |
| Artifact restored | 1 | 1 | Same skill repairs; three tests pass |

The JSON companion embeds the observed process IDs, candidate bindings, test
counts, measurement hashes, and exact test/resource summaries. The no-learning
route deliberately has no separate fallback solver: the controls establish this
route's dependence on the retained artifact, **not superiority over every solver**.
The repair is returned as a proposal tested in copied trees, not silently applied
to a live user project.

## Remaining work

The fixtures are intentionally small. Advanced cross-repository engineering
curricula, scale/contention, crash/power-loss durability and bounded backup
recovery still need qualification. Retrieval remains capped at 128 candidates
per language. Scope/context declarations and typed oracle results remain trusted
inputs; a malicious caller can fabricate them. The real project oracle is
copied-tree execution, **not an OS sandbox**. Passing tests does not prove every
request requirement or arbitrary unseen behavior. Weak compatibility predicates
can still accept wrong edits, but can no longer honestly be labeled behavioral
assurance through this interface.
