# Live scoped repair-transfer comparison

Run `python3 -m canonical.tools.live_scoped_transfer_benchmark_v1` from the repository root. The JSON output contains one teaching result and rows for three arms: learning disabled with production fallback search, statement-only retained repair, and opt-in operator/semantic retained repair. Each arm runs in a fresh interpreter, each case has an isolated copy of the source-only SQLite lesson, and each target has a separate project. Fallback search can itself teach a skill, so per-case database isolation matters.

The benchmark uses six **known, constructed variants of one Python boundary lesson**, plus an already-correct inclusive negative control. It is not a blind benchmark, a comparison of other-branch solvers, a test of arbitrary tasks, or a proof of permanent memory. The live path checks the declared tests before and after applying a patch; the independent audit runs in a separate interpreter on a larger finite integer grid. Neither test suite proves behavior on all inputs. The negative control is already satisfied and therefore does not exercise the recall verifier; `test_retained_operator_generalization_integration_v1.py` separately verifies recall rejects an inclusive candidate and concurrent invalidation.

`elapsed_ms` is the entire `apply.run` call, including its production test gates and any fallback search, but excludes project construction, the independent audit and the initial lesson. `oracle_calls` is the session's count, which may include teaching after fallback; it is not solely a count of recalled candidates. Timings and results depend on the machine and workload. The test code runs in copied directories but is not an OS security sandbox; use only trusted fixtures.

To enable generalized proposals in a retained-repair request, add `"allow_operator_generalization": true` inside the existing `retained_learning` settings, alongside the scoped `TEST_SUITE` contract and context. It defaults to false. At most 16 statement and 16 generalized proposals per eligible skill are considered, duplicates are skipped, and all accepted proposals still require current scoped candidate-bound test evidence and the store's post-verification liveness check. This is a proposal mechanism, not authority to bypass the rest of the repair gate.
