**OPUS_5_5_USEFUL_CAPABILITY_OWNERSHIP_V1**

**EFFECTIVE FRONTIER INTELLIGENCE = BRAIN-OWNED CAPABILITY MECHANISMS + EXTERNAL JIT KNOWLEDGE + GENERAL COMPUTATION SUBSTRATE**

Brain-owned capability mechanisms may be:

- state machines/verifier/recovery logic;
- adapters and learned deltas;

- new Brain-invented mechanisms when they satisfy the same ownership and verification requirements;
- compositions of the above.

## Parameter-obsolescence principle

Neural parameters are not the objective.

Before retaining learned parameters, Brain must attempt to delete their function through:
- JIT knowledge;
- deterministic computation;
- existing Brain capabilities;
- software/tools;
- cheaper verified substitutes.

Only the residual learned behavior may justify retained neural machinery.

No claim is made that every capability is cleanly separable or that a neural kernel must exist.

## Specimens, donors, and owned capabilities

An external system may be:
- a capability specimen showing that behavior exists; or
- a white-box donor exposing an already-existing learned mechanism.

Neither role is ownership.

White-box donor path:
external donor demonstrates C
-> define C independently of donor identity
-> subtract solved/non-neural functions
-> locate/extract the smallest sufficient existing mechanism
-> causally validate ablation/rescue/specificity
-> package as Brain-owned capability capsule
-> remove donor from target-capability runtime path
-> verify exact Brain route >= Opus 5.5
-> save and inherit permanently

If the only operative instruction is "call model/service X because X already has C", C is not owned.

## Capability internalization tests

Promotion requires all existing ownership tests plus, when harvesting is used:

1. RESIDUAL-CONTRACT TEST
   The target excludes knowledge and functions already solved elsewhere.

2. DONOR-ADMISSIBILITY TEST
   Exact donor provenance, license, version, hashes, and intended derivative use are recorded.

3. CAUSAL-SUFFICIENCY TEST
   Ablation degrades the target and rescue restores it under matched conditions.

4. SPECIFICITY TEST
   The artifact does not win by contamination, answer leakage, or unacceptable collateral capability loss.

5. HELD-OUT TEST
   Final evidence was not used to select/tune/minimize the capsule.

6. DONOR-DELETION TEST
   The target capability remains available after removing the donor as target-capability provider.

7. FULL-DEPENDENCY ACCOUNTING TEST
   Every unavoidable learned/runtime dependency is disclosed and counted.

8. MINIMIZATION TEST
   Unnecessary learned scope was tested for deletion after sufficiency was established.

Failure means no full ownership credit.

## Invention and redesign admissibility

The former absolute rule **UNDERLYING_CAPABILITY_INVENTION_FORBIDDEN** is superseded.

The verified Tournament countermodel proves that the terminal acceptance equation does not logically require a winning mechanism to pre-exist.

The governing rule is:

- search, reuse, compose, extract, minimize, or substitute first when those routes reach verified terminal ownership faster;
- invention or architecture redesign is admissible when it is the fastest sound $0 incremental-spend route to a Brain-owned equal-or-better capability, or when existing realizable routes are falsified or dominated;
- invented mechanisms receive no special credit and must satisfy the same capability, ownership, donor-independence, anti-contamination, held-out, dependency-accounting, minimization, and verification gates as every other route;
- do not invent merely because proof is missing;
- do not forbid invention merely because an older strategy preferred acquisition.

This is an optimization-policy repair, not capability credit.

## Acceptance law

For target capability C:

**Capability(ExactBrainOwnedRoute(C)) >= Capability(Opus5.5(C))**

External specimen/donor performance alone does not satisfy this equation.

## General cognition substrate boundary

A general computation/cognition substrate may be used, but its hidden target behavior must not be relabeled as Brain-owned capability.

Brain must own the operative capability configuration and the target capability must materially depend on that configuration.

If replacing the Brain package with "use external model/service X" preserves substantially the same target capability, X is the capability provider and the route is not owned.

## JIT knowledge non-smuggling boundary

External/JIT knowledge may supply facts, documents, measurements, specifications, task inputs, world-state observations, and admissible precommitment discriminators.

It may not be used to disguise opaque dynamic target-task solving, external policy selection, runtime-generated target-specific plans that substitute for missing Brain capability, or held-out answer/evaluator leakage.

## Anti-contamination

Untouched qualification tasks must not be read, trained on, tuned against, donor-selected against, or otherwise consumed before final qualification.

## Knowledge boundary

Knowledge stays external/JIT except compact state/evidence needed for reproducibility.

Harvesting knowledge into parameters is not progress toward capability ownership.
