## Terminal target

Project Brain's terminal target remains:

**OPUS_5_5_USEFUL_CAPABILITY_OWNERSHIP_V1**

Brain must permanently possess the useful capabilities of Claude Opus 5.5 at equal-or-better useful performance.

Knowledge remains external/JIT. Capabilities do not.

## Core theory

**EFFECTIVE FRONTIER INTELLIGENCE = BRAIN-OWNED CAPABILITY MECHANISMS + EXTERNAL JIT KNOWLEDGE + GENERAL COMPUTATION SUBSTRATE**

Brain-owned capability mechanisms may be:
- deterministic software/algorithms;
- skills/procedures/workflows;
- prompts/policies/routers;
- state machines/verifier/recovery logic;
- adapters and learned deltas;
- expert/module subsets;
- compact learned capsules;
- shared Brain-owned cognition kernels;
- compositions of the above.

## Parameter-obsolescence principle

Neural parameters are not the objective.

Before retaining learned parameters, Brain must attempt to delete their function through:
- JIT knowledge;
- deterministic computation;
- existing Brain capabilities;
- software/tools;
- cheaper verified substitutes.

Only the residual learned behavior may justify retained neural machinery.

No claim is made that every capability is cleanly separable or that a neural kernel must exist.

## Specimens, donors, and owned capabilities

An external system may be:
- a capability specimen showing that behavior exists; or
- a white-box donor exposing an already-existing learned mechanism.

Neither role is ownership.

White-box donor path:
external donor demonstrates C
-> define C independently of donor identity
-> subtract solved/non-neural functions
-> locate/extract the smallest sufficient existing mechanism
-> causally validate ablation/rescue/specificity
-> package as Brain-owned capability capsule
-> remove donor from target-capability runtime path
-> verify exact Brain route >= Opus 5.5
-> save and inherit permanently

If the only operative instruction is "call model/service X because X already has C", C is not owned.

## Capability internalization tests

Promotion requires all existing ownership tests plus, when harvesting is used:

1. RESIDUAL-CONTRACT TEST
   The target excludes knowledge and functions already solved elsewhere.

2. DONOR-ADMISSIBILITY TEST
   Exact donor provenance, license, version, hashes, and intended derivative use are recorded.

3. CAUSAL-SUFFICIENCY TEST
   Ablation degrades the target and rescue restores it under matched conditions.

4. SPECIFICITY TEST
   The artifact does not win by contamination, answer leakage, or unacceptable collateral capability loss.

5. HELD-OUT TEST
   Final evidence was not used to select/tune/minimize the capsule.

6. DONOR-DELETION TEST
   The target capability remains available after removing the donor as target-capability provider.

7. FULL-DEPENDENCY ACCOUNTING TEST
   Every unavoidable learned/runtime dependency is disclosed and counted.

8. MINIMIZATION TEST
   Unnecessary learned scope was tested for deletion after sufficiency was established.

Failure means no full ownership credit.

## No-capability-invention law

Underlying useful capability invention remains forbidden.

Allowed creation includes:
- integration;
- encoding/configuration;
- extraction/minimization tooling;
- packaging;
- routing;
- persistence;
- adapters representing an already-existing donor capability;
- verification;
- recovery.

If no realizable existing route can be acquired under hard constraints, record unresolved/theory-falsification evidence.
