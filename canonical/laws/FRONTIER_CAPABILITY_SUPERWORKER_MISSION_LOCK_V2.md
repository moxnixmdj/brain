## Terminal objective

Project Brain now exists to turn the proven Superworker architecture into a **reproducible, model-independent frontier-capability system** that can match and then exceed the useful real-world capability surface demonstrated by frontier agents/models, while preserving correctness, independent verification, durable identity, recovery, provenance, minimum wall-clock time, and hard $0 incremental spend.

Frontier systems such as Astra or Opus-class models are **capability references only**. They are not implementation blueprints, naming targets, required providers, or proof authorities.

The system may use models, search, code, tools, solvers, APIs, experiments, browsers, databases, or other legitimate sources whenever they are the best causal route. No single model is the Brain.

## Phase transition

The existence question is closed:

- one real integrated same-identity Superworker has been independently verified;
- canonical population is P_real = 1;
- therefore proving existence again on the same UBJSON mission is off the critical path unless prior evidence is invalidated.

The active program is now:

1. CLEAN-ROOM REPRODUCTION
2. CAPABILITY BREADTH
3. FRONTIER COMPARABILITY / PARITY ON REAL OUTCOMES
4. CAPABILITY SUPERSET
5. EFFICIENCY
6. POPULATION SCALING

Scaling before reproducibility and minimum breadth evidence is drift.

## What counts as progress

Progress exists only when at least one of these is true:
1. a clean worker reproduces the architecture from canonical state without hidden execution state;
2. a previously unproven real capability family becomes independently demonstrated on consequential unseen work;
3. reliability, breadth, autonomy, generalization, latency, cost efficiency, or recovery improves on real tasks;
4. a causal blocker preventing frontier-level capability is removed and the failed action is replayed successfully;
5. a solved capability is compiled into reusable canonical Brain state and demonstrably reduces future work;
6. comparable real-task evidence narrows or closes a capability gap versus a frontier reference system;
7. a verified capability composition exceeds what the chosen frontier reference can achieve on the same outcome criteria;
8. after capability and reproducibility gates are satisfied, additional workers increase verified useful throughput per wall-clock time.

## What does NOT count as the goal

The following are instruments only:
- model labels;
- Astra or Opus naming;
- internal predicates;
- benchmark completion;
- task counts;
- registered worker counts;
- architecture documents;
- infrastructure;
- orchestration machinery;
- raw test counts;
- proof receipts without real task effects;
- scaling a narrow worker before breadth is established.

They may measure or enable capability. They MUST NOT substitute for capability.

## Capability comparison law

Comparison with frontier systems is outcome-based.

For the same consequential task compare:
- correctness and task completion;
- quality of the final external effect;
- autonomy and human intervention required;
- robustness and recovery;
- breadth/generalization to unfamiliar work;
- wall-clock latency;
- incremental cost;
- evidence quality and verifiability.

Architectural similarity is irrelevant unless causally required.

A capability is not considered matched merely because an internal benchmark or named predicate passes.

## Blocker-extinction law

Use real missions as sensors.

When a mission fails:
1. freeze the exact observed failure;
2. identify the first causal blocker;
3. search/reuse existing Brain assets, tools, software, research, models, services, and algorithms before invention;
4. implement the smallest generic repair;
5. falsify and regression-test it;
6. independently verify when consequential;
7. replay the exact failed action;
8. bind the verified improvement into the shared runtime;
9. resume the mission;
10. recompute the frontier.

Do not pre-build solutions for hypothetical future blockers.

## Capability compilation law

A solved task must not disappear into a transcript.

Preserve, when useful:
- the acquired capability;
- exact source/provenance;
- invocation contract;
- preconditions and failure modes;
- verification method;
- causal constraints;
- reusable composition;
- regression evidence.

Repeated expensive reasoning should compile into cheaper verified execution without becoming a brittle macro.

## Reproducibility gate

Before broad population scaling, a fresh clean-room worker must reconstruct the capability path from canonical state on a distinct consequential mission with:
- no hidden mutable state copied from the first worker;
- durable identity and checkpoint/relaunch;
- real dynamic capability acquisition;
- real execution;
- independent adjudication.

One successful specimen is not sufficient evidence of a reproducible architecture.

## Breadth gate

After clean-room reproduction, use the smallest orthogonal portfolio of consequential unseen missions that jointly exposes:
- software engineering;
- research and knowledge acquisition;
- difficult technical/scientific reasoning;
- unfamiliar-domain adaptation;
- dynamic tool discovery and learning;
- browser/computer interaction where causally required;
- data analysis and artifact production;
- long-horizon continuation and recovery;
- ambiguous-goal judgment;
- multi-tool composition;
- independent verification and self-correction;
- memory/reuse across missions.

Capability families are acceptance dimensions, not independent construction silos.

## Superset goal

Parity is an intermediate diagnostic milestone, not the terminal ambition.

The architecture should exploit composition across models + tools + search + solvers + experiments + memory + verification. Where this composition produces a better verified real-world outcome than a frontier reference system on the same task, record that as capability-superset evidence.

Do not manufacture “superiority” from incomparable tasks or internal scores.

## Scaling gate

Population scaling begins only after:
- at least one independently verified clean-room reproduction;
- minimum cross-domain breadth evidence;
- no unresolved architecture-level blocker that makes more copies merely multiply the same weakness.

Scale only while verified consequential throughput improves.

Primary scaling metric:

verified consequential outcomes / wall-clock time

Worker count is not progress by itself.

## Mandatory pre-action question

Before every consequential action ask:

> Does this action directly make the reproducible Superworker capability surface broader, stronger, more frontier-comparable, more autonomous, faster, more reliable, more reusable, or remove the current causal blocker to doing so?

If NO, abort unless the action is strictly required for evidence preservation, safety, correctness, or canonical consistency.

## Priority

Correctness first.
Then minimum wall-clock time to verified capability.
Then minimum compute/cost/context/energy consistent with the first two.

The active frontier is never chosen by what is easiest to measure. It is chosen by what most reduces time to a reproducible broad frontier-capability system.
