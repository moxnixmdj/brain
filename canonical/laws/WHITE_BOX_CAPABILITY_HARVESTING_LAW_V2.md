## Purpose

Acquire already-existing learned capability mechanisms from legally usable inspectable donors without adopting the donor as Brain, importing redundant knowledge, or retaining the donor as an opaque runtime capability provider.

A donor is a temporary causal source. The target artifact is the smallest resource-feasible Brain-owned capability capsule. Donor performance alone gives zero ownership credit.

## Residualization

Before harvesting, remove from the target contract everything already solved by:
- Brain-owned deterministic software or algorithms;
- exact symbolic computation;
- external/JIT knowledge retrieval;
- durable Brain memory/state;
- tools and artifact engines;
- already-owned capability packages;
- cheaper verified substitutes.

Only the surviving residual learned behavior may justify learned retention.

## Donor admissibility

A donor is admissible only when exact identity/version, operative artifact hashes, inspectability basis, license/derivative constraints, provenance, and intended use are recorded and compatible with the mission's spend and ownership constraints.

Unclear redistribution rights fail closed.

## Elicit before teach

Before extracting or training a new learned residual, test whether the behavior is already latent in an owned substrate using increasing durable-information budgets:
1. zero-byte composition;
2. deterministic configuration/router/policy;
3. tiny elicitation/control artifact;
4. sparse/low-rank residual;
5. compact learned module;
6. larger machinery only after smaller classes fail.

A tiny unlock artifact is retained only if the complete unavoidable substrate dependency is already Brain-owned and fully counted.

## Allowed extraction classes

Allowed classes include:
- same-lineage checkpoint or task-vector deltas;
- sparse or low-rank weight deltas/adapters;
- MoE expert/module subsets;
- layer/head/circuit subsets when causally demonstrated;
- compact distilled residual models/modules;
- explicit algorithms or procedures recovered from donor behavior;
- compositions of the above.

Probes, SAEs, attribution maps, activation features, and correlations are diagnostic until converted into a donor-independent operative mechanism that passes promotion.

## First-failure residual extraction

Do not default to copying complete teacher trajectories or broad donor behavior.

Prefer:
Brain attempt -> earliest irreducible missing transformation -> extract/teach only that transformation -> rerun -> repeat only if another irreducible failure remains.

This is an optimization rule, not permission to weaken the capability contract.

## Causal sufficiency and ownership tests

Before promotion:
1. TARGET CONTRACT: define residual useful behavior independently of donor identity.
2. DONOR POSITIVE CONTROL: donor/reference route demonstrates the target under the chosen evaluation.
3. ABLATION: disabling the proposed mechanism materially degrades target capability.
4. RESCUE: restoring/transplanting it restores target capability under matched conditions.
5. SPECIFICITY: no answer leakage, unrelated knowledge smuggling, or unacceptable control damage.
6. HELD-OUT GENERALIZATION: final evidence was not used for selection, tuning, pruning, ranking, or minimization.
7. DONOR DELETION: promoted Brain route runs without the donor supplying the target capability at runtime.
8. BRAIN ROUTE VERIFICATION: exact future Brain configuration verifies at or above the required frontier bar.
9. FULL DEPENDENCY ACCOUNTING: every unavoidable runtime dependency is disclosed and counted.
10. RESOURCE-BOUNDED MINIMALITY: smaller mechanism classes were tested or explicitly bounded and the retained route satisfies runtime/reliability constraints.

Failure of any required test means no full ownership credit.

## Capability capsule

Every promoted harvested capability must conform to:
- canonical/governance/WHITE_BOX_CAPABILITY_CAPSULE_SCHEMA_V2.json

The capsule must contain operative artifacts, dependency closure, license/provenance, causal evidence, held-out evidence, byte accounting, runtime bounds, interference controls, invocation contract, hashes, verifier, recovery/fallback, and donor-deletion proof.

## Byte accounting

Apply canonical/laws/RESOURCE_BOUNDED_CAPABILITY_BYTES_LAW_V1.md.

Count values, masks/indices, routers, decoder/loaders, unavoidable base dependencies, configuration, and persistent control state.

Separate B_exec, B_verify, B_proof, and B_JIT.

## Minimization

After sufficiency is established, recursively test deletion/reduction of:
- experts;
- ranks;
- layers;
- heads;
- precision;
- prompt scaffolding;
- context requirements;
- auxiliary learned modules;
- incidental package dependencies;
- duplicated shared substrate.

After every material deletion, rerun target and control verification.

Optimization target is minimum total durable resource cost subject to capability and operational bounds, not parameter count alone.

## Joint factoring

Do not minimize capsules independently when shared cognition exists.

Factor duplicated verified substrate into one Brain-owned shared kernel only when every affected route remains re-executable, dependency accounting remains exact, no material regressions appear, and the shared artifact is itself owned and versioned.

Do not assume a shared neural kernel is necessary.

## Invention boundary

A newly invented mechanism is not white-box harvesting merely because a donor inspired it.

Invention/redesign is governed by Mission Lock V9 and must pass the same ownership and verification standards, but it must be labeled honestly.

## Contamination

Untouched qualification tasks may not be read, trained on, tuned against, donor-selected against, or otherwise consumed before final qualification.

## Stop rule

Stop harvesting immediately when a simpler already-owned, deterministic, software, invented, or reusable route reaches the same required bar with lower total mission cost and equal-or-better reliability/verifiability.
