## Mission

Find already-existing realizations of Opus 5.5 useful capabilities, configure them into Brain, verify equal-or-better useful behavior, and retain them permanently.

Knowledge is retrieved externally/JIT and is not the capability inventory.

## Route race

For each target capability compare:
1. already-owned Brain route;
2. existing configurable software/tool/runtime;
3. existing library/CLI/solver;
4. existing configured model/agent capability;
5. composition of existing capabilities.

The winning route is the fastest route that can become a durable Brain-owned configured capability at or above the Opus 5.5 bar.

There is no capability-invention lane.

"BUILD" in older OBS artifacts is reinterpreted under V5 as **build integration glue only**, never invent the underlying useful capability.

## Acquisition product

The product is not an external supplier reference.

The product is the durable Brain capability package that captures configuration, invocation, dependencies, routing, verification, recovery, and regression evidence.

## Knowledge use

During capability acquisition and normal task execution, retrieve current knowledge externally/JIT. Do not turn retrieved knowledge into a required permanent Brain knowledge warehouse.

## Failure response

When a route fails:
1. preserve evidence;
2. ask whether another existing realization replaces the route;
3. switch if faster;
4. repair only integration/configuration if the selected realization remains best;
5. never start inventing the underlying capability.

## Search stop

Stop search and configure when:
- the candidate can plausibly meet/exceed Opus 5.5;
- configuration into Brain is feasible;
- no unresolved challenger is likely to dominate enough to justify delay.

## Terminal condition

The program is complete when every target useful Opus 5.5 capability is either:
- VERIFIED_OWNED_EQUAL_OR_BETTER; or
- explicitly unresolved with evidence sufficient to challenge/falsify the theory under current hard constraints.
