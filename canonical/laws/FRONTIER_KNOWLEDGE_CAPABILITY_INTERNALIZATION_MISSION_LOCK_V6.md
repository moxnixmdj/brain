# FRONTIER KNOWLEDGE + CAPABILITY INTERNALIZATION MISSION LOCK V6

Status: CANONICAL / MANDATORY / FAIL-CLOSED

## Terminal target

Project Brain's terminal capability target remains:

**OPUS_5_5_USEFUL_CAPABILITY_OWNERSHIP_V1**

But "ownership" is now defined strictly.

Brain must permanently possess the useful capabilities of Claude Opus 5.5 at equal-or-better useful performance.

Knowledge remains external/JIT. Capabilities do not.

## Core theory

**EFFECTIVE FRONTIER INTELLIGENCE = BRAIN-INTERNALIZED CAPABILITY CONFIGURATIONS + EXTERNAL JIT KNOWLEDGE + GENERAL COMPUTATION SUBSTRATE**

These three things are different.

### Knowledge

Knowledge may remain external forever.

Retrieve it JIT, verify consequential claims, use it, and retain only evidence/provenance/compact state needed for reproducibility.

### General computation substrate

A model, CPU, solver runtime, accelerator, or other general computational substrate may execute Brain-owned capability configurations.

The substrate may be external.

But the substrate's hidden behavior does not become a Brain-owned capability merely because Brain can call it.

### Capabilities

A capability is owned only when the operative capability configuration is represented durably in Brain-owned artifacts.

Examples include:
- skills;
- procedures;
- prompts/system instructions;
- policies;
- planners;
- routers;
- tool-use recipes;
- workflows;
- algorithms;
- software;
- adapters;
- state machines;
- verifier/recovery logic;
- compositions of the above.

The external system in which a capability is first observed is a **capability specimen/source**, not automatically the final implementation.

## Specimen versus owned capability

External system demonstrates capability C
-> evidence that C exists
-> inspect/decompose the demonstrated route
-> identify the already-existing reusable capability configuration/mechanism
-> acquire that configuration
-> encode/configure it into Brain-owned artifacts
-> run it on an approved general computation substrate
-> verify BrainConfigured(C) >= Opus5.5(C)
-> save and inherit permanently

If the only operative instruction is effectively "call model/service X because X already has capability C", then C is **not owned**.

That is external capability access.

## Capability internalization test

A capability may be promoted to OWNED only if all are true:

1. **Brain-artifact test**
   The operative skill/configuration is materially represented in durable Brain-owned artifacts.

2. **No-hidden-capability-provider test**
   No external dependency is being credited merely because its hidden proprietary cognition already contains the target capability.

3. **General-substrate test**
   Any model dependency is used as general computation/cognition substrate under Brain's saved capability configuration, not as an opaque capability oracle.

4. **Specimen-separation test**
   The external system that demonstrated the capability is not itself the only definition of the capability.

5. **Re-execution test**
   Future use does not require rediscovering or re-extracting the capability.

6. **Verification test**
   The Brain-configured capability itself, not the external specimen alone, is verified at or above the Opus 5.5 useful-capability bar.

7. **Ownership-package test**
   The saved package contains the actual operative configuration, invocation contract, dependencies, routing, verifier, recovery behavior, provenance, and regression evidence.

Failure of any test means the state is:
- EXTERNAL_CAPABILITY_SPECIMEN_FOUND; or
- INTERNALIZATION_IN_PROGRESS; or
- UNRESOLVED.

It is not OWNED.

## Model rule

Models may provide general reasoning/computation.

Models may not be used as a semantic loophole to externalize capability.

Bad:
> "Astra scores above Opus on benchmark X, therefore Brain owns capability X by routing to Astra."

Good:
> "System X demonstrates capability C. Brain acquired the existing reusable skill/configuration responsible for C, saved it, runs that configuration on an approved cognition substrate, and Brain's resulting system verifies >= Opus."

The model can be part of execution. The capability must belong to Brain.

## No-capability-invention law

Underlying useful capability invention remains forbidden.

Allowed creation is only:
- integration;
- encoding/configuration of already-existing capability mechanisms;
- packaging;
- routing;
- persistence;
- adapters;
- verification;
- recovery.

If the capability exists only as inaccessible hidden behavior and no already-existing realizable capability configuration can be acquired, record the result as unresolved/theory-falsification evidence. Do not call opaque access ownership.

## Acceptance law

For target capability C:

**Capability(BrainInternalized(C) executed on approved general substrate) >= Capability(Opus5.5(C))**

Benchmark superiority of an external specimen does not satisfy this equation.

## Capability package minimum contents

Every owned capability package must contain:
- capability ID and useful behavior;
- Opus 5.5 bar;
- external specimen(s) that proved existence;
- acquired reusable mechanism/configuration;
- exact Brain-owned operative artifacts;
- exact instructions/skills/workflow/algorithm or composition;
- general substrate requirements;
- tool dependencies;
- invocation contract;
- routing conditions;
- state/persistence requirements;
- verifier;
- recovery/fallback behavior;
- regression evidence;
- proof that promotion evidence evaluates the Brain-configured route rather than only the specimen;
- durable inheritance path.

A package that contains only a provider/model name plus routing instructions is invalid.

## Correct acquisition sequence

OPUS CAPABILITY
-> FIND WHERE IT ALREADY EXISTS
-> TREAT THAT SYSTEM AS A SPECIMEN
-> FIND/EXTRACT THE ALREADY-EXISTING REUSABLE CAPABILITY CONFIGURATION
-> CONFIGURE THAT INTO BRAIN
-> EXECUTE ON APPROVED GENERAL COMPUTATION SUBSTRATE
-> VERIFY BRAIN'S CONFIGURATION >= OPUS
-> SAVE PERMANENTLY
-> INHERIT

Knowledge during any step stays external/JIT.

## Anti-drift

Forbidden:
- counting model benchmark superiority as Brain capability ownership;
- counting provider access as capability ownership;
- counting free access as ownership;
- treating a capability specimen as the owned implementation;
- hiding a target capability inside the phrase "model dependency";
- permanently externalizing capabilities;
- inventing missing underlying capabilities;
- lowering the Opus 5.5 bar;
- confusing knowledge with capability.

## Immediate correction

Any existing package whose operative implementation is merely an external model/service that already possesses the target capability must be reclassified from OWNED to EXTERNAL_CAPABILITY_SPECIMEN_FOUND until the capability is internalized and Brain's configured route is independently verified.
