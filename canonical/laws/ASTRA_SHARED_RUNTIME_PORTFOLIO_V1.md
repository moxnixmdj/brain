## Terminal objective

Make the actual Astra capability surface real in one shared Project Brain runtime as fast as possible.

## Core correction

The ten Astra capability families are acceptance dimensions and sensors of one system.
They are NOT ten construction projects.

Do not serialize development through one mega-mission.
Do not fragment development into ten capability silos.

Use:

**one shared ASTRA_RUNTIME + one accountable runtime owner + the smallest orthogonal portfolio of consequential cross-domain missions running concurrently.**

The mission portfolio is chosen to expose all important capability deficits and cross-capability interactions as early as possible.

## Optimization target

Minimize:

T_ASTRA_REAL = max(
  time until all required capabilities are operational in the shared runtime,
  time until those capabilities work together end-to-end
)

Mission selection should maximize:

(new capability exposure + cross-capability interaction exposure + uncertainty eliminated)
/
wall-clock time

This is a set-cover + adversarial-testing problem, not a benchmark program.

## Minimal orthogonal development portfolio

Maintain the smallest portfolio that jointly forces the entire target surface.

Default starting portfolio:

A. Research -> science -> professional artifact -> GUI delivery
Forces fresh research, source judgment, quantitative/scientific reasoning, code/data tools,
professional artifacts, GUI/browser action, memory, scope handling, orchestration, efficiency.

B. Unfamiliar software/environment mission
Forces unfamiliar repository/environment understanding, debugging, terminal/browser use,
unknown tool acquisition, novel adaptation, recovery from wrong hypotheses, research,

Forces changing requirements, interruption/restart, uncertain scope, unfamiliar external
information, tool failures, multiple artifact types, consequential decisions, judgment,

These are starting shapes, not sacred task identities.
Replace any mission when another portfolio provides greater capability exposure per wall-clock time.

## One runtime, global inheritance

All portfolio missions use the exact same evolving ASTRA_RUNTIME.

A fix learned in any mission becomes available to all missions immediately.

No separate mission-specific architectures.

## Blocker-local swarm law

When any portfolio mission fails:

1. freeze the exact observed failure;
2. identify the smallest causal capability deficit;
3. unleash the largest useful available worker/tool/research force on that exact deficit;
4. race direct reuse, composition, minimal adaptation, and only then invention;
5. search existing Brain assets, connected tools, plugins, OSS/GitHub, services, papers,
   models, deterministic algorithms, and other legitimate $0 routes;
6. reproduce and falsify competing candidates;
7. independently verify the first adequate solution;
8. bind the winner into the shared runtime;
9. replay the exact failed action;
10. resume every affected mission immediately;
11. make the verified capability globally inheritable.

Workers provide WIDTH below a real blocker. They do not create unrelated work.

## Strong-cognition allocation

Use strongest available cognition only at high-multiplication points:
- deciding whether a failure is causal;
- decomposition;
- branch selection;
- ambiguous diagnosis;
- synthesis of conflicting evidence;
- integration choice;
- frontier recomputation.

Use cheaper cognition for procurement/search/integration/reproduction/falsification where adequate.
Use deterministic computation for deterministic work.

## Capacity law

Real execution/inference capacity is a multiplier and may be expanded in parallel.

Capacity expansion is never a prerequisite to capability closure.
Every useful worker available now attacks current blockers now.
Additional legitimate $0 capacity joins immediately.

Registered identities, queues, and worker counts are not capacity.

## Task admission law

A task may stay on the critical path only if it:
1. advances a current shared-runtime portfolio mission;
2. repairs a frozen blocker observed by those missions;
3. improves a reusable capability that demonstrably reduces expected T_ASTRA_REAL; or
4. performs final qualification after operational closure.

Otherwise it is paused/superseded.

Standalone capability silos, benchmark preparation, speculative infrastructure,
worker-count projects, and premature qualification are off critical path.

## Qualification boundary

Capability-forcing portfolio missions create and harden the runtime.

Formal qualification begins only after the same shared ASTRA_RUNTIME completes the
portfolio with verified effects and recovery.

Then freeze exact bytes/config/state and run:
- independent family evidence;
- hidden generalization;
- fresh cross-domain integrated hidden missions;
- failure recovery;
- unknown-domain/JIT acquisition;
- durable state;
- independent verification;
- clean-room full-stack reproduction.

Qualification proves the runtime. It does not build it.
