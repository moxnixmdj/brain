## Mission

Acquire, verify, inherit, reuse, and recursively obsolete the fastest sufficient routes for useful frontier-model capabilities until frontier implementations are no longer uniquely necessary.

## Outer control loop

**REAL TASK
-> RECURSIVE OBS
-> SELECT FASTEST SUFFICIENT SURVIVING ROUTE
-> EXECUTE
-> VERIFY REAL EFFECT
-> INHERIT
-> OBS INHERITED SYSTEM FOR DELETIONS
-> FRESH REUSE
-> RECOMPUTE**

OBS is the scheduler-level decision procedure. It is not a post-hoc review.

## Recursive OBS

Before consequential implementation, evaluate:
1. goal;
2. capability;
3. blocker;
4. proposed solution;
5. verification method;
6. inherited system;
7. OBS itself.

The selected route is provisional and loses authority when material state changes.

## Route race

Use deletion-first order:

**DELETE -> BYPASS -> REUSE -> SUBSTITUTE -> COMPOSE -> REPAIR -> BUILD**

When a capability is genuinely required, compare:
1. inherited Brain capability;
2. connected tool/system;
3. existing software/library/CLI/API/database/solver;
4. composition;
5. JIT acquisition;
6. deterministic/specialized substitute;
7. smallest adequate model supplier;
8. adaptation;
9. invention.

Correctness first. Among sufficient routes, minimize wall-clock, then incremental cost, then complexity.

## Search stop

Do not research forever.

Once an adequate route exists and remaining plausible competitors cannot justify the delay needed to evaluate them, execute the adequate route.

## Blocker rule

A blocker is actionable only if recursive OBS proves it is causal on the fastest surviving route and cheaper to remove than to route around.

Otherwise mark the blocker obsolete.

## Verification rule

Prefer direct independent verification of the real effect.

Synthetic benchmark/gate/evaluator work is allowed only if direct verification is unavailable or inadequate and OBS proves the synthetic method is the fastest reliable substitute.

## Inheritance rule

The capability package is the product.

Immediately after inheritance:
- identify queued work made unnecessary;
- close/supersede it;
- search for adjacent capabilities now covered;
- attempt fresh reuse without rediscovery.

## Real-output accounting

Only these change progress:
- reusable capability inherited;
- verified consequential real task completed;
- fresh reuse passed;
- frontier dependency removed;
- residual gap localized enough to change the frontier.

OBS passes and avoided actions are efficiency/compliance evidence, not progress.

## Support budget

Without real output:
- first support action requires an exact live blocker;
- second requires falsification of the first support route;
- after two, recompute the capability target;
- never continue by incrementing synthetic gate numbers.

## Immediate mode

The active operating mode is REAL_CAPABILITY_ACQUISITION_WITH_RECURSIVE_OBS.

For the selected real mission, run recursive OBS first, then execute the fastest sufficient surviving route. Do not modify governance again unless execution exposes a genuine generic control defect.

## Terminal condition

The program ends when the useful frontier capability surface has been systematically processed and every target has either:
- a verified reusable equal-or-better route used on real work; or
- a precise evidence-backed irreducible residual gap.

The goal is not a better benchmark factory.

The goal is a system that actually does the work while continuously deleting unnecessary machinery.
