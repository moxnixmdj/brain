## 6. A defect the wave did **not** record

Verification of its own scripts surfaced one it missed, and it is in the same class it names:

**The test suite writes to tracked memory state on every run.** Executing one test file mutates
`canonical/astra_runtime/state/ASSOCIATIVE_MEMORY_V1.json` — `accesses` increments on all 12 entries,
`last_accessed` is rewritten with the wall clock:

```
-   "accesses": 6590,        +   "accesses": 6591,
-   "accesses": 12953,       +   "accesses": 12954,
-   "accesses": 8830,        +   "accesses": 8831,
```

Mechanism: `computer_env_v1.py:1616-1673` calls a transcript `recall()`, which reaches
`associative_memory_v1.recall()` (`:242` — `rec["accesses"] = … + 1`) and persists to the default
state path. **Consequences:** (a) any clone that runs tests ends up with a dirty tree — the patch
documents exactly this for its own instrument (`experience_v1.json`) but *not* for the suite;
(b) `accesses` is the denominator of `importance()` (Beta prior in `importance()`/`_relevance`),
so **test traffic is indistinguishable from use** and inflates the score of entries whose referents
are dead `/tmp` paths — compounding the §3 "9 of 12 memory entries credit a deleted referent" defect;
(c) it is a **declaration with no enforcement**, which is precisely the ratio the wave says is the
project's core pathology.

Suggested disposition: give the memory a test-scoped state path (env override) or make `_save`
refuse to write when the caller is a test process; then re-baseline `accesses` so the metric counts
real retrieval.
