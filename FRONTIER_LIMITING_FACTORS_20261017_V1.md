`OPEN_ENDED_CAPABILITY_OPTIMIZATION_NO_FINITE_FRONTIER_MODEL_OR_BENCHMARK_DEFINES_FINAL_MISSION_COMPLETION`

This is not a blocker to be removed; it is the definition. "Reaching the terminal goal" can only
mean two measurable things, and they are different:

- **T (terminal truth):** `truth.achieved` flips true. Requires the owner, in person, to edit the
  guard's countersign constant. **No agent can do this. Ever.**
- **C (capability):** the creature becomes whole and credited — every bound capability reachable,
  runnable, and exercised on unseen instances by an independent oracle, with zero model.

Everything below limits T, C, or both.

## Layer 5 — Instrument defects (one fixed, three open)

### 5.1 FIXED: dependency declarations drifted from the code
The liveness probe read only hand-written `source.packages`. Measured, it was wrong in both
directions: 2 capabilities over-blocked (adapters have proven stdlib fallbacks), 11 under-blocked
(reached binaries through their import graph and declared nothing). The heartbeat reported
**60/67 runnable here; the truth was 52/67.** Fixed by deriving dependencies from the transitive
import closure as a second independent witness. Two seedless runs on one commit: blocked 7 → 15.

### 5.2 OPEN: reachability counts *selection*, not *execution*
Proven: `chart.raster.scene_graph.v1` is selected by the router for a chart goal (so it counts as
reachable) but **fails to execute**, because the goal grammar binds tick *values* while the
capability needs `[pixel, value]` anchors only the OCR predecessor produces. `R` is overstated by
an unknown amount, at least 8.

### 5.3 OPEN: the heartbeat verdict does not gate on runnability
`alive_errors()` checks only: family pass rates, out-of-scope fail-closed, and
`NOT_REACHABLE`/`ROUTED_ELSEWHERE` counts. It does **not** include
`external_dependency_missing_here`. A capability can be non-runnable and the heartbeat stays green.

### 5.4 OPEN: a PR cannot cite the receipts it creates
The drift guard resolves counterexample-receipt blobs against the **base** commit and silently
drops paths absent there (`enforce_goal_hierarchy.py` ~line 1145). So the receipts a PR adds can
never be its own counterexample evidence; only pre-existing receipts can be cited.

## Layer 8 — Throughput and infrastructure

### 8.1 The heartbeat is within 2m12s of its own timeout
Measured: last successful public heartbeat took **27m48s**; `timeout-minutes: 30`.

But measured `solve()` time is only **46.6 s for 272 instances** (30 families). At the heartbeat's
50 instances/family that is ~4.3 minutes. **~97% of the wall clock is setup and per-case
dependency work (apt install, pip install, npm install, pypi probes), not measurement.**

Time is dominated by the Python repair cluster:

| Family | ms/instance | share |
|---|---|---|
| PYTHON_FAULT_LOCALIZE | 1915.6 | 32.9% |
| PYTHON_REPAIR_STRICT_PROGRESS | 953.4 | 16.4% |
| PYTHON_AST_PATCH_SEARCH | 779.9 | 13.4% |
| PYTHON_REPAIR_TEST_GUIDED | 456.4 | 7.8% |
| CODEC_MSGPACK_NPM | 387.1 | 6.6% |
| CODEC_CBOR | 373.3 | 6.4% |

**Consequence:** the ceiling on families-per-run is set by setup overhead and the 30-minute job
timeout, not by the Brain. Adding the ~25 families from the plan will breach the timeout unless
the setup is cached (a warm dependency layer) or families are sharded across parallel jobs.

### 8.2 No concurrency control on the heartbeat
`.github/workflows/live-brain-heartbeat.yml` has **no `concurrency:` group**. Observed at 01:19 UTC:
three heartbeat runs in flight simultaneously (01:02, 01:15, 01:19), each ~28 minutes. Every PR
triggers a full run and they stack. With ~13 PRs planned that is ~6 hours of runner time
competing for the same budget, and it is why runs appear as `cancelled` in the history.

### 8.3 Dated infrastructure deadlines
- **Ubuntu 26 runner migration: 2026-10-19** — two days from now. Observed live in the last
  heartbeat's annotations: *"The ubuntu-latest label will migrate to Ubuntu 26 beginning October 19,
  2026."* The heartbeat's apt line is pinned to Ubuntu package versions; a runner image change can
  break the exact dependency set the 67 capabilities were qualified against.
- **Node.js 20 deprecation:** `actions/checkout@v4`, `actions/setup-python@v5`,
  `actions/upload-artifact@v4` are being forced onto Node 24. Warning only today.

### 8.4 This sandbox
No apt (network allowlist is github/npm/pypi only), no general egress, `cadquery` missing
`libGL.so.1`. Consequence: 15 of 67 capabilities cannot be run here at all, and the 7 unmeasured
families that need network or apt binaries cannot be developed or debugged locally — every
iteration costs a ~28-minute public-runner round trip.

### 8.5 Billing is NOT a blocker (correcting the previous plan)
V2 listed hosted-Actions billing as its #1 blocker ("prestep failures, 100/100 runs, 11+ days").
**Measured today: false.** Runs execute normally — PR #4739 triggered heartbeat, referee, drift
guard, measure and verify, all running. Some individual runs do fail with *"This run likely failed
because of a workflow file issue"* (e.g. 38985054520), which is a prestep/workflow problem, not
billing. Do not plan around billing.

### 9.1 The base-commit race (measured, and it bit this PR)
The drift guard compares the intent's declared `canonical_base_commit` against the PR's actual
base sha and fails `RECURSIVE_OBS_STALE_BASE_COMMIT` when they differ.

Measured: **main advanced 15 commits in 43 minutes** (00:34 → 01:17), all from the autonomous
capability-receipt campaign seeded by #4725 — a rate of **0.35 commits/minute, ~1 every 2.9 min**.
PR #4739 failed exactly this check. Fix: rebase onto the freshest main and push immediately.

The intent block also requires ~6 fields duplicated byte-identically across the top level and
`recursive_obs` (`expected_parent_frontier_change` ≡ `expected_parent_level_state_change`,
`stop_condition` ≡ `stop_condition`), plus blob shas for the active pointer and every cited
receipt. Five violations on first submission; all were bookkeeping, none were defects in the work.
