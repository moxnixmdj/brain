## 6. ADVERSARIAL REVIEW (2026-10-14, same session) — this plan was NOT optimal as written; corrections are binding on execution

**Verdict: core direction optimal, execution design not. Six defects found; fixes below supersede §§2–3 where they conflict.**

1. **"Optimal" was unprovable as stated.** The live scheduler forbids invented scalar weights and returned `vector_complete = []`; with interval vectors incomplete, no total order exists. Correct claim: this plan is *Pareto-nondominated among complete-vector-free options*, not "optimal". Any stronger claim requires a proved tradeoff contract (`scalarization_requires_proved_tradeoff_contract`).
2. **HLE/Mystery/Finance-E2E lanes were under-specified.** HLE is the only score lane with zero owner dependency (public MIT harness; harness-binding P≈0.80 ≤2d) yet had no numbered execution step; MysteryMechanism certificates passed (sky Step 6) with no promotion-packet step. FIX — insert **Step 2.5**: (a) bind HLE-with-tools harness publicly, run capability-proposition compile before any score talk; (b) convert Mystery polytope + interval-frontier certificates into a promotion packet; (c) convert Finance sky-Step-4 certificate into the E2E certificate packet that Step 7a only "armed". P(at least one of three yields a verified delta ≤7d) = 1−(0.55×0.60×0.65) ≈ 0.79 under independence; deflate for shared verifier capacity (see 4) → **≈0.70**.
3. **One-intent-per-PR serialization contradicts "single burst".** Nine steps cannot merge as one PR under blocker-lease dedupe. FIX — execution is one *burst of work*, nine *serialized intents* in dependency order: 4c/4b (zero-execution proofs) → 1a (path-filter) → 2a/2b → 3 → 4a → 2.5 → 5 → 6 → 7 → 8/9 packets. Merge queue, not burst, is the real critical path; expected merge throughput is the binding rate, not authoring speed.
4. **Independence assumptions overstate joint math.** Steps 1, 2, 2.5, 3, 5 share two scarce resources: independent-verifier capacity and (post-0a) Actions minutes. Joint expectations in §3 are therefore upper bounds. Deflated planning values: E[14d truths] 6–8 (from ~14 sum-of-parts), P(≥1 owner channel 30d) stays 0.75 (channels are truly independent), P(donor 10/10) stays ~0.60, P(T ≤120d) stays 0.08–0.15. No ordering change follows — parallelism still dominates — but no decision should use the undeflated sums.
5. **Carrier plan had an unexplored cheaper branch.** Before waiting on billing/self-host, shard the full regression into PR-transported capsule runs (the proven public-runner pattern) partitioned by suite; private code travels in the PR, results return as receipts. It cannot replace the *private full-system* gate for promotion credit (gate text requires full private current-main regression), but it can pre-clear ~most suites so the eventual gated run is a single confirmation, cutting Step 1b failure risk 0.30 → ~0.15. FIX — run capsule-sharded pre-regression in parallel with Step 0; keep the gated run as the sole credit-bearing execution.
6. **Two user actions were missing.** (f) Enable branch protection + required checks in GitHub UI (connector cannot; user can, 2 minutes — closes `REPOSITORY_PROMOTION_ENFORCEMENT`'s human half).
