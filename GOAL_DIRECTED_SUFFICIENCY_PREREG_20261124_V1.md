## 4. §3 verdict and the one bottleneck

**TRUE bounded:** one verified source experience plus a closed, reachable question space can settle a named goal gap; an admitted abstraction can be stored externally and replayed on fresh instances; reading can be cheaper and safer than learning; raw trajectory accumulation can be refused.

**FALSE universal:** a finite advanced experience cannot identify arbitrary unseen rules, hidden state, source authority, mid-task changes, GUI/DOM semantics, natural-language intent, or a sound verifier that the system cannot represent. One trace is one point; same observed facts can have opposite outcomes; a guide can contradict its parser; a self-certified pass can be reward hacking.

**UNPROVEN:** hardest-open Nov 2026 coding/computer-use score, arbitrary unseen GUI/browser qualification, own trained weights end-to-end, independent cloud verifier, GUI/DOM oracle, and §6. `truth.achieved` remains false.

**Single local bottleneck selected:** a **refusable, goal-directed sufficiency boundary** that converts a named gap into either one discriminating observation or a refusal, and admits only abstractions that survive fresh-instance checking. Without this boundary, more scanning, memory, search, weights, or benchmark calls multiply false successes. This is a prerequisite, not the ultimate qualification bottleneck; the ultimate bottleneck remains independently verified end-to-end performance under §6.

## 5. Ultimate-minimal plan, rejected ideas, and kill attempt

**Keep exactly one composed mechanism, using existing primitives:**

1. `learn_or_read_v1.decide` first. If reading determines the action, return `READ_ONLY__NO_STORE_WRITE`; no scan, no fetch, no question, no store write.
2. Deny caller-supplied authority bits (`force_learn`, `store_now`, `trust_retrieved`, `independent_verified`, `execution_authorized`).
3. Deny any candidate store payload containing raw path/argv/content/trace/answer/reward fields.
4. `applicability_v1.insufficiency_witness`: if repetition cannot repair the observation vocabulary, refuse and name the new observable required.
5. If `current_version` exceeds every evidence version, refuse until a fresh dynamic-environment observation exists.
6. For a named missing goal fact, use `active_question_v1.ask` / `settlement_v1.settle` over a **closed** regime space and reachable probes. Accept `ASK__SETTLED_NAMED_GAP` only when EIG settles and the winner predicts a non-`UNKNOWN` answer. Refuse outside-space, open-space, blind-instrument, and underdetermined cases.
7. Otherwise use `contrast_selection_v1.select_contrast`; require an informative reachable contrast. Use `perfect_algorithm_v1.generalize` and `admit` on fresh instances. Store only `rule_id`, goal family/environment kind/scope, relation signature, artifact span, abstract mechanism signature, evidence digest, and admission counts. No raw trace, path, argv, content, exact answer, or reward.
8. External store must be inspectable, removable, restorable, and digest-stable across a second process. A different-code local verifier process must recompute canonical digests, expected decision classes, negative refusals, store cleanliness, and false authority fields. This is a local recheck, **not** independent attestation.

**Rejected first choices, with reasons:** exhaustive scan as strategy (project measured goal-directed first and unsafe unbounded sweeps); open-space EIG / BED-LLM as runtime dependency (proposal-generator failure, forbidden model calls); “learn everything” append-only memory (negative transfer and memory pollution); raw trajectory or exact action cache (owner explicitly rejects dumb exact experience and 2026 evidence agrees); LoRA/ASCENT-style persistent weights (owner-law prohibition, insufficient verified fuel, no GPU/torch/open-weight substrate; also needs a verifier before permanence); JIT web retrieval as runtime authority (guide/version mismatch, self-contradictory docs, egress constraints); model judge; benchmark-specific workflows; running Pro V2/TB 4.1/OSWorld 2.1 without required container/VM/assets/budget; treating leaderboard numbers as this system’s score; merging or editing truth counters.

**Kill attempt before acceptance:** the design is killed if any negative arm stores a row, if any raw field appears in the store, if a caller authority bit changes the decision, if same-fact opposite outcomes are treated as learned, if stale evidence is admitted, if an outside/open/blind hypothesis space saves, if fresh-instance admission failure saves, if the store cannot be removed/restored with the same digest, or if the separate verifier cannot reproduce the canonical digest and expected classes. Any such failure must be corrected before a formal receipt or reported as a failed design.
