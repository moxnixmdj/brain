# Creature information continuity — draft

This is producer-run engineering work, not independent verification, an admission, or evidence that the whole creature is complete.

## What changed

The assembled creature previously treated every finished attempt as a closed goal after a restart, including failures. Only explicit `ok is True` outcomes now count as closed; failed attempts are counted across restart so the existing two-attempt parking rule survives a reboot. Legacy caller-authored boards still contain callable checks that are not serialized and must be re-authored after reboot. The generic injected performer still reports its own outcome; it is not an independently trusted verifier.

The creature now supports one narrow typed information question: whether a caller-specified capability ID is **listed** in the fabric's bound-capability catalog. The admitted question's claim, source, target and fixed check identifier are saved, not arbitrary callable code. The default step calls the real fabric `CATALOG`, validates the response and compares the answer to another local registry read. The result is persisted with the completed attempt and can be recovered in another process. Listing is not proof of invocability, safety, independent verification, or execution authority. The local registry check is not independent: the catalog uses the same loader. `learn=False` is passed, but catalog is a special route; this is not a claim of a system-wide learning-off mode.

An injected generic performer cannot answer this typed question. Invalid or inconsistent output leaves the question unfinished. Two failed attempts park it, including across reboot. An unfinished question cannot be silently replaced; an explicit abandon removes it without claiming success. A prior generic work item with a colliding ID does not satisfy the typed question. Only one typed question is stored at a time; its ID is stable per target, so a previously completed question does not refresh automatically when a catalog later changes. The target is supplied by the caller: this is not automatic discovery or proof that the existing missing-inspector goals have been accomplished.

The initial life grant is saved at boot, even when no step has run. Life is charged and saved before invoking the performer. A kill during a test-controlled in-flight operation leaves the charged life, an interrupted attempt, and an open question. This is a process-kill test, not a power-loss or concurrent-writer guarantee. State lives in trusted local storage, is not authenticated, and its several files are not one atomic transaction. No guarantees are made for hostile filesystem races, storage corruption, competing processes, or external effects interrupted in flight.
