## 1. Why the composed edit is evidence, and where it stops

The [controlled project](canonical/tools/probe_staged_composition_v1.py) has a function that counts characters but is asked to sum the input's UTF-8 bytes. The file itself defines one function from `str` to `bytes` and another from `bytes` to `int`. Neither alone is a repair. The [proposer](canonical/swe_kernel/local_type_paths_v1.py) searches backwards from a localized return's annotation to an in-scope argument via one or two module-local unary functions. A type match licenses a test, not a commit. It doesn't need an answer expression, a library of UTF-8 fixes or a remote proposer.

In a fresh offline room the old staged worker (`bee38f70`) found a failure but emitted **0 B**. With the shared proposer (`d17cb7c1`), `label` was reached in the failing test; the reported winning mechanism was `LOCAL_TYPED_RETURN_PATH`; the **301 B** captured patch replaced `len(value)` with `measure(octets(value))`. Applying it on a clean base and checking eight ASCII, non-ASCII, empty, NUL and repeated inputs changed **1/8 → 8/8**. Repair command times **4.901 → 9.638 s**; this repair wasn't faster. A second construction reproduced both patch hashes, both code manifests and all eight outcomes. The staged store correctly **refused** to file the unbound `measure,octets` subtree (`learned_skill_id=null`). This is a deliberately solvable engineering test, not a new hard task or a hard-task memory transfer. [Captures and fresh checks](canonical/Immediate_Results/staged_composed_return_control_20261126_v1.json).

The **full-runtime** transferable object is different. Previously the repo-native method could call a failing pytest-only module “already green” via a unittest fallback. It also tried to read the wrong field from history templates and reversed the fold tuple order. Even after fixing those, storing the deepest tree diffs for the composed repair produced `len → measure` and `x → octets(x)` separately. Recalling three templates and running Stage 1 did **not** mean a learned repair had fired: the receiver was actually solved by repeating the typed search.

The revised route retains a small joint expression when both changes are needed. It abstracts unchanged formal parameters, keeps supplier names literal, reconstructs the demonstrated replacement, and renders only the affected source span. It refuses a bad reparse or the loss of an input/import dependency. Teacher `local.label` → receiver `local.scale`, different input and tests: the reloaded journal's winning **template ID, teacher ID and exact candidate digest** are checked. With just that teacher retracted and the store reopened, retrieval returns **zero** templates; `LOCAL_TYPED_RETURN_PATH` solves the receiver again. That is causation for **which mechanism fired**, not an extra solved task. No learned-arm speed advantage was measured. Distinct-project benefit over exact replay is still missing. [Regression and deletion controls](canonical/tests/test_witnessed_native_route_v1.py).

The journal is outside the checkout. A selected-test flip enqueues a certificate (failed test identities, test hashes, edit hashes) and bounded templates. A transaction converts one pending ticket into a teacher event and supported template records. A replay doesn't increase support; forgetting one of two teachers leaves the other. `READ_ONLY` doesn't consolidate; `OFF` doesn't read/write the journal. Records are hypotheses, not signed proof; consumers still rerun native tests. Logical retraction retains an audit history, **not** physical erasure. Credentials, full repositories and raw trajectories are not required journal inputs.

Other concrete fixes: candidate and baseline pytest run on fresh product copies, with full passed/failed/skipped identities compared. Empty collection, changed test identities, runner errors, stale path-based component cache, duplicate method names, escaped product symlinks, timed-out workers and lost child payloads have controls. The CoW wrapper had called a nonexistent constructor signature and its caller swallowed the exception. It now bounds a real assertion-slice run or reports `UNMEASURED`; class/fixture tests go to the real project runner, and a slice pass never authorizes skipping that runner. A scratch cwd and process group are useful for trusted tasks, **not OS confinement**. Inputs are still primarily Python; nominal annotations, changed lines, preexisting tests and discovered suppliers constrain coverage.

## 3. A browser match that wasn't a completed task

The producer receives a prompt, live top-level same-origin WebMCP metadata/DOM and optionally one teacher record. It matches a handle, re-discovers/checks the schema before invocation, and reports the observable transition. A fresh local page demonstrated stamping a quoted label. Four reset predictions distinguished **literal** from **slot** with one input different from the teacher's; the actual page displayed the new label. The contrast took **1.426 s** including the real reset. The result identifies the slot *among those two possibilities*, not a universal rule. Later code requires the measured counterfactual before permitting slot substitution. It also rechecks read-only annotations at call time on recognized read questions; this limited language recognizer is not a general safety policy.

**First freeze.** Four actual pages advertised **3/7/1/25 tools**. In 104 runs there were **76 no groundings, 27 actions without verified goal, 1 unconfirmed invocation**. Empty/raw/lifted each matched **6/36** graded steps, **1/26** complete; deleted **5/34**, one complete, one ungraded case. Summed per-trial seconds **63.700/48.399/56.352/66.027** respectively. No receiver reused the teacher to earn a goal. Not calling anything on a read question is also not answering it. The initial policy could even call `set_canvas_size` with `{}` on a read question; that was an observed unwanted mutation, not a success. [Frozen predictions](canonical/Immediate_Results/webmcp_receiver_predictions_20261126_v1.json) · [upstream matcher](canonical/Immediate_Results/webmcp_receiver_call_grades_20261126_v1.json).

**Second freeze.** On 15 *remaining* prompts, original vs read-gated, explicit-sequence policy: **15 → 17** step records, **6 → 7/33** matched steps, **1 → 2/15** whole call matches, summed **24.039 → 48.575 s**. New handles were observed twice. This measures the combined policy change, not a pure memory intervention. [Paired predictions](canonical/Immediate_Results/webmcp_followup_predictions_20261126_v1.json) · [call grades](canonical/Immediate_Results/webmcp_followup_call_grades_20261126_v1.json).

**Post-freeze effect check.** We replayed frozen actions on fresh copies for **all six** follow-up Doors prompts; separate grader uses only ordered visible headings/messages, never tool names, to judge effects. No-step and real UI-button controls calibrate each predicate. For “open second door, then return” the revised trace was **Choose a Door → The Coral Cove → Choose a Door**; original stopped in the cove. For “dance, hide and return”, that *same* round trip correctly failed: neither intermediate effect occurred. For “open third door, then return”, the upstream call matcher gave both arms full credit for `openDoor3`; the browser still showed **The Wizard's Attic**. Both failed the user goal. A human-style positive control cast light to enable Return, then actually returned. The first grader read too early on navigation (11 of 12 agent rows missing); retaining that attempt, a goal-independent settled readback yielded all 12 measured. [Both readbacks and controls](canonical/Immediate_Results/webmcp_doors_effects_20261126_v1.json). This is an author-defined, post-hoc effect measure on pinned public pages, not an upstream effect score, independent study or fix tuned on those calls.

**Fresh reproduction:** rebuilding from the pinned pages and rerunning the published recipe changed only one initial call-grade row: the previously unconfirmed Doors index 4 in the deleted arm now confirmed `openDoor1`, **one of two steps, not a complete match**. All four arms now had 1/26 complete matches and 6/36 matched steps. All 30 follow-up call grades and **all 24 ordered state trajectories and effects** (including controls) matched the first settled readback. The earlier missing observation remains recorded, not relabelled. [Comparison](canonical/Immediate_Results/witnessed_route_checks_20261126_v1.json).

## 4. Memory that retracts isn't yet memory that understands

An append-only SQLite event has transaction time, valid time, witness, value and specific parent versions. The latest view propagates signed support changes along affected reverse edges; a past query still evaluates the DAG at the requested cutoffs. Deleting one justification doesn't retract an independently supported value. A previously true dependent with no support becomes *unknown*, not the older value. Tests cover a late correction, two supports, ordered visibility after restart, migration from the old schema, a killed uncommitted writer, and 140 disordered updates compared against the historical walk across nine keys. This is a Boolean support multiset, not a general DBSP or constant-time arbitrary inference. [Store](canonical/swe_kernel/witnessed_revision_store_v1.py) · [differential tests](canonical/tests/test_witnessed_revision_history_v1.py).

Both model and creature doors expose `revision_memory` with structured operations and now also `ingest_turn` / `answer_question`. One user turn is atomic. The text reader handles limited explicit statements/conditionals; it doesn't silently turn another speaker's suggestion into fact. It is not handed a MEME graph. On the seven-session redistributed `pl_001` slice the frozen reader had 82 turns / 8 grounded statements at the before cutoff, 97 / 10 after: **zero strict answers in both phases**. Eleven questions lacked a unique slot; the one retrieved value also failed strict comparison. Cumulative reader time at the last answers was **0.014/0.019 s** (not total setup time). Its original SQLite file held ten `set` events and **no derived event** in 16,384 bytes; fast queries over this file are not successful dialogue reasoning. A perfect retraction engine cannot propagate a fact never extracted or retrieve it for a question never grounded. Re-running the frozen reader reproduced all 12 predictions apart from elapsed time, including their evidence IDs. The new structural tests do not change that grade. ## 5. What to do with the repository and the frontier research

The [15-organ / nine-PR audit](canonical/verification/WITNESSED_ROUTES_AUDIT_20261126.md) identifies which mechanisms to reuse, which drivers read post-fix data, and where branch names had been mistaken for commits. The model's **fixed atlas**, 42 existing queries at top 5: routed hit **20/21 frontier, 19/21 native**; source hit **13/21, 15/21**. These are hits against the atlas's own domain membership, not calls or solves. Historical “0.33 route recall” need not apply to this later router/scorer. Rebuilding the atlas in scratch at `32f7e89e` scanned 3,353 non-test modules and gave the same four hit counts. The model artifact, registry and authority tables were not regenerated or promoted. More routing alone would not have supplied a failing Ansible requirement or made an empty workspace executable.

- **One-shot induction:** retain a *set of competing explanations* until a permitted input with an independent desired output distinguishes them. CoW is for cheap predictions over trusted pure functions; use an actual reset room for I/O. Agreement among learner-generated variants alone isn't intent. Transfer requires the rule to fire, an external improvement and a matched deletion, not just a retrieved record.
- **Continual learning:** keep inspectable teacher evidence and replaceable hypotheses outside parameters. In MEME v2 the authors report average default Cascade/Absence near **3%/1%** on 100 episodes; moving the expensive reasoning into file-based ingest partially closed that gap at ~70× baseline cost. This motivated separating dialogue grounding, dependency maintenance and answer selection, rather than benchmarking only a gold fact graph. [1](https://arxiv.org/abs/2605.12477) TTT-Discover trains a 120B model at test time; JitRL avoids gradients but modulates **LLM logits**. Neither is evidence for a zero-model solver. [1](https://arxiv.org/html/2601.16175v1) [1](https://arxiv.org/abs/2601.18510)
- **Long-horizon coding:** the SlopCodeBench paper measured 36 problems / 196 checkpoints, best strict rate **14.8%** then, not a permanent ceiling. The author's November update reports **16.3%**. The reason to run sequential checkpoints is to catch architecture that gets harder to extend, not to compare our 2 blank starts to either percentage. [1](https://arxiv.org/abs/2603.24755) [1](https://gabeorlanski.github.io/posts/slop-moves-up/)
- **Computer use:** Agent S4 reports **21.3% binary** on 108 OSWorld V2 tasks with an evolved interface repository **and a 27B model**. Improving an interface is useful; inheriting that score isn't. OSWorld **2.1** pins task classes, complete gated assets, website release and VM/provider images; we verified the release tag `3d778a3c`, not an environment or trajectory. No OSWorld run without these inputs and a working provider. [2](https://arxiv.org/html/2610.28601) [1](https://github.com/xlang-ai/OSWorld-V2/releases/tag/osworld-v2.1)

## 6. Status and next decisive experiment

**Still open:** independent hard SWE, terminal and real desktop completion; nontrivial single-experience advantage on new tasks that disappears on deletion; safe long-horizon recovery; robust dialogue grounding. The historical image HARD-51 result is **0/51 agent, 0/51 nop, 51/51 reference** on a different revision. This branch has no new locked-image HARD-51, official TB, MEME, FixedBench, SlopCodeBench or OSWorld score. No Docker/KVM here; the previously attempted Actions dispatch returned **403**. The complete MEME dialogue release wasn't present on the allowed GitHub sources inspected; a smoke fixture is not that release. These are measurement boundaries, not estimates of missing results.

Prioritize the next loop by the observed failure: (1) on an untouched receiver, acquire a **public, requirement-specific failing observation** on a bounded budget; (2) compare no-store, exact, generalized and one-entry-deleted arms with identical permissions and budgets; (3) freeze each patch/trajectory before applying a separate task verifier and preservation checks. Don't add examples from these graded tasks to the producer. If all arms still acquire no failing observation, do not tune template retrieval. If a two-step browser policy reaches the last page but skips a required intermediate effect, grade it false. For MEME, verify extraction on fresh permitted dialogue *before* scaling the storage engine. Run full release images/desktop only on a provisioned evaluator and keep missing grades null. No benchmark leaderboard claim or merge until the joint criterion is actually met.
