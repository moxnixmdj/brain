## 4. Continual / instant learning and clarification

- **Primary paper:** [When Continual Learning Moves to Memory, arXiv:2604.27003](https://arxiv.org/abs/2604.27003), submitted 2026-04-29. Abstract page `hasMore=false`; full HTML [2604.27003v1](https://arxiv.org/html/2604.27003v1) chunk 0 fetched, `hasMore=true` (11 chunks).
- **Clarification paper:** [Ask or Assume?, arXiv:2603.26233](https://arxiv.org/pdf/2603.26233), chunk 0 fetched, `hasMore=true` (9 chunks).
- **Environment adaptation:** [ACuRL, arXiv:2602.10356v1](https://arxiv.org/abs/2602.10356v1), submitted 2026-02-10, revised 2026-05-11. Abstract page `hasMore=false`.

Verbatim from memory paper abstract:

> "Memory-augmented LLM agents offer an appealing shortcut to continual learning: rather than updating model parameters, they accumulate experience in external memory, seemingly sidestepping the stability-plasticity dilemma of parametric learning. We show that this challenge does not disappear but resurfaces at the memory level."

> "Across sequential-task experiments in ALFWorld and BabyAI, we find that abstract procedural memories transfer more reliably than detailed trajectories, while negative transfer disproportionately harms the hard cases. Moreover, finer-grained memory organization is not universally beneficial: designs that yield strong forward transfer can simultaneously induce severe forgetting."

Verbatim from the memory HTML introduction:

> "irrelevant memories may be recalled, introducing retrieval pollution; useful experiences may be displaced by other retrieved items under a finite context window, creating context competition; and as the memory store grows across tasks, relevant experience may become harder to identify, resulting in memory dilution."

Verbatim from Ask or Assume? abstract:

> "we systematically evaluate the clarification-seeking abilities of LLM agents on an underspecified variant of SWE-bench Verified. We propose an uncertainty-aware multi-agent scaffold that decouples underspecification detection from code execution. Across both proprietary and open-weight frontier LLMs, our scaffold achieves a 69.40% task resolve rate ..."

The paper's contributions state it uses frontier LLMs (Claude Sonnet 4.5 and Kimi K2.6) and simulated user interaction. That is an input about *when* clarification helps; it is forbidden as a runtime dependency here.

Verbatim from ACuRL abstract:

> "we introduce ACuRL, an Autonomous Curriculum Reinforcement Learning framework that continually adapts agents to specific environments with zero human data. The agent first explores target environments to acquire initial experiences. During subsequent iterative training, a curriculum task generator leverages these experiences together with feedback from the previous iteration to synthesize new tasks tailored for the agent's current capabilities."

> "our method effectively enables both intra-environment and cross-environment continual learning, yielding 4-22% performance gains without catastrophic forgetting on existing environments. Further analyses show highly sparse updates (e.g., 20% parameters) ..."

ACuRL updates parameters and uses a CUAJudge; it is evidence that adaptation is hard, not an allowed runtime component.

**Implication for design:** external store alone does not solve learning; raw trajectories harm hard cases; abstract relations are safer; clarification works in model-based scaffolds but cannot be borrowed. This supports the §2 boundary refinement: store relation *texts*, recompute predicates from the new machine's own runs, refuse when recomputation fails, and never count guides/web as capability.

## 5c. Iteration-7 grammar-transport and fresh-process verification sources

The project sweep found that iteration 6 still hardcoded one term family (`computed_deictic_holder_shape_v1`) in producer code and carried only relation texts. `THE_HYPOTHESIS_GRAMMAR_IS_THE_BOTTLENECK_20261122_V1.md` measured 8/30 real fixes needing a second production; `THE_VOCABULARY_IS_THE_ARTIFACT_20261125_V1.md` measured that a fixed `{CARD, MULTISET}` vocabulary cannot state a rename. This round therefore researched **grammar descriptors**, **formal replay**, and **action/evidence transport**, not more traces, breadth, or model calls. The 23 additional primary pages, 85 distinct chunk reads and 85 invocations are build-time evidence only; no model, paper, leaderboard, adapter, or external verifier became a runtime dependency.

### Grammar and relation transport

- **Shared effects, native realizations:** [Zero-Shot Compositional Generalization for Embodied Manipulation, arXiv:2611.22797](https://arxiv.org/html/2611.22797) (chunks 0–4, final `hasMore=false`) maps a source demonstration through calibrated geometry into a shared tool-space target, then lets each foreign robot's native decoder realize that target through its own kinematics; held-out robot–task combinations are evaluated by closed-loop execution. Its learned visual policy is forbidden here, but the transfer grammar is directly relevant: **carry a declarative relation/grammar description, recompute its concrete predicates in each machine's own call log, and verify by execution, not by exact action labels**.
- **Compact discrete primitives:** [Gradient-Based Program Synthesis with Neurally Interpreted Languages, ICLR 2026 / arXiv:2604.18907](https://arxiv.org/html/2604.18907v1) (chunks 0–11, final `hasMore=false`) learns a discrete symbolic-like program vocabulary and recurrent interpreter; gradient search recomposes primitive tokens for OOD lengths (99% Shift-L, 100% Shift-P, 91% Comp-I). Its trained encoder/decoder, Gumbel search and millions of training tasks are forbidden as runtime weights, but it supports the minimal reusable-primitive grammar: a small allowlisted feature vocabulary with sequential/local recomputation, not a world-fact warehouse.
- **Lifted predicate registry:** [Continual learning and refinement of causal models through dynamic predicate invention, arXiv:2602.17217v1](https://arxiv.org/html/2602.17217v1) (already in §5b) formalizes lifted dynamics that depend on object relations rather than identities, recursive abduction/predicate invention, a canonical-hash global predicate registry, and depth-bounded search. Iteration 7 reuses only the **canonical descriptor hash + identity-free relation** idea; no MIL planner or learned world model is shipped.
- **Formal verification of invented predicates:** [ADVENT, arXiv:2607.01585](https://arxiv.org/html/2607.01585) (chunks 0–5, final `hasMore=false`) pairs LLM predicate invention with Prolog execution over examples; formal verification raises average concept-learning success from 58% to 80%, and a knowledge pool adds up to +31 points on compositional concepts, but an unfiltered pool can dilute simple concepts. Its LLM proposer is forbidden; the surviving mechanism is **formal execution checks on concrete runs + selective grammar reuse**, which iteration 7 implements as an allowlisted descriptor and fresh-process replay.

### Verification transport, receipts, and process evidence

- **Verification gap:** [Autonomous Research Agents: A Survey of AI Scientists and the Verification Gap, arXiv:2608.05179v1](https://arxiv.org/html/2608.05179v1) (method/result/final chunks read through chunk 80 `hasMore=false`) codes 26 works / 24 runnable systems: code release 83%, but seeds or execution traces only 38%; benchmark/task-success and LLM-as-reviewer each 62%; real/wet-lab external oracle only 8%; no LLM-era system in the corpus demonstrates an externally validated in-loop oracle. This is why iteration 7 calls a fresh process **transport verification**, not independent identity verification.
- **Builder/verifier separation:** [Who Verifies the Builder?, arXiv:2610.28667](https://arxiv.org/abs/2610.28667) and the [assure-harness repository](https://github.com/besionisrael/assure-harness) report that a verifier in a fresh context detects more seeded faults than the builder's own tests, while a verifier from another provider did not add detection. The repository explicitly lists limitations: 3 services, 46 seeded faults, possible bias toward Claude, and model/provider confounds. Its model-written test suites are not used; the structural separation is.

- **Exact auto-verifiable constraints:** [VERITAS, arXiv:2606.22783](https://arxiv.org/html/2606.22783) (chunks 0–3 and final chunk 12) uses cryptographic hash constraints that are cheap to verify and non-optimizable semantically, with an incomplete-enumeration failure case in the tail.
